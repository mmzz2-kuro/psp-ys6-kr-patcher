# 061. Ys VI 저장 확인 이미지 블록 오프셋 및 분할 수정 계획

## 상태

- 완료 (2026-08-20)

## 문제

- `tools/patchdata/ys6_additional_images/source_images/save-confirmations.png`에
  `block_offset: 1` 교정이 적용돼 있다.
- 원본 ISO의 `saveicon2.dds.z`를 오프셋별로 다시 렌더링한 결과, 이 리소스는
  오프셋 0에서 프레임이 정상 좌표에 놓인다.
- 현재 오프셋 +1 이미지는 4×4 블록 스트림이 한 칸 밀려 좌측에 4픽셀 빈 영역이
  생기고 우측·마지막 블록이 잘못 이어진다.
- 현재 `source_parts/save_confirmations`는 전체 높이 128픽셀을 40/40/48픽셀로
  단순 분할한다. 실제 아틀라스의 문구와 패널 경계가 이 분할선과 일치하지 않아
  문구가 잘리거나 인접 패널이 같은 조각에 섞인다.
- 매니페스트 문구 순서와 원문도 실제 이미지와 다르다.
  - 실제 위: `このデータをロードしますか？`
  - 실제 가운데: `このデータを上書きしますか？`
  - 실제 아래: `このデータを削除しますか？`
  - 현재 첫 항목의 `このデータをセーブしますか？`는 이미지와 일치하지 않는다.

## 목표

- `save-confirmations.png`를 올바른 블록 순서와 논리 좌표로 재생성한다.
- 세 문구를 실제 아틀라스 위치에 맞는 독립 편집 조각으로 제공한다.
- 사용자가 편집한 문구가 독립 `saveicon2.dds.z`와 런타임
  `init.bin/static_tex.dds.z` 그림 69에 동일하게 적용되게 한다.
- 향후 GUI에서 `prepare`를 다시 실행해도 잘못된 균등 분할과 오프셋이 재발하지
  않게 한다.

## 수정 범위

1. `save_confirmations`의 블록 오프셋을 `1`에서 `0`으로 변경한다.
2. `source_block_offset_applied` 상태를 새 오프셋 기준으로 정리한다.
3. 원본 ISO의 독립 `saveicon2.dds.z`에서 다음 파일을 다시 생성한다.
   - `source_images/save-confirmations.png`
   - `source_parts/save_confirmations/*`
4. 매니페스트의 문구를 실제 화면 순서와 원문으로 정정한다.
   - `line_01`: 로드 확인
   - `line_02`: 덮어쓰기 확인
   - `line_03`: 삭제 확인
5. 단순 40/40/48 수평 분할을 폐기한다.
6. 오프셋 0 원본에서 각 문구의 실제 픽셀 경계를 측정하고, 4×4 DXT 블록 경계로
   확장한 최소 편집 영역을 정의한다.
7. 문구가 하나의 직사각형으로 안전하게 분리되지 않거나 공용 배경·우측
   `Yes/No/Delete` 조각과 겹치면 `pieces` 기반 다중 조각 영역을 사용한다.
8. `tools/scripts/ys6_additional_image_patch.py`가 추가 이미지 영역의 `pieces`를
   지원하도록 확장한다.
   - 준비 시 여러 조각을 하나의 편집 PNG로 이어 붙임
   - 합성 시 같은 좌표 정의로 각 조각을 원위치에 복원
   - 수정된 조각이 포함된 4×4 블록만 재인코딩
9. 우측 `Yes`, `No`, `Delete` 버튼 및 패널 배경은 번역 대상에 포함하지 않고
   원본 블록을 유지한다.
10. 기존 `embedded_runtime` 관계를 유지해 독립 파일과 `static_tex` 그림 69를
    함께 갱신한다.
11. RGBA 변경 영역 검사에서 알파뿐 아니라 RGB 채널도 포함한다. 알파를 유지한 채
    글자 색상만 바꾼 편집도 변경 블록으로 인식해야 한다.

## 좌표 결정 원칙

- 모든 원본 좌표와 조각 크기는 4픽셀 경계에 맞춘다.
- 각 편집 PNG에는 한 문구만 포함한다.
- 다른 문구, 다른 패널, 우측 선택지 조각이 편집 PNG에 들어가지 않게 한다.
- 글자 주변의 그림자·외곽선은 포함하되 불필요한 대형 배경 영역은 제외한다.
- 512×128 전체 아틀라스에서 사용하지 않는 투명·예약 영역은 원본 그대로 둔다.
- 최종 좌표는 측정 결과와 확인용 접촉 시트에 기록한다.

## 검증

1. 블록 오프셋 검사
   - 원본 payload의 오프셋 0 렌더와 새 `save-confirmations.png`가 픽셀 단위로
     동일한지 확인
   - 좌측 4픽셀 빈 밀림과 우측 마지막 블록 래핑이 사라졌는지 확인
   - 오프셋 +1 결과와 새 이미지가 다름을 확인
2. 분할 검사
   - 각 조각에 대응 문구 하나만 포함되는지 확인
   - 문구 글자·그림자·외곽선이 잘리지 않는지 확인
   - 인접 패널과 `Yes/No/Delete`가 섞이지 않는지 확인
   - 조각 좌표와 크기가 모두 4픽셀 정렬인지 확인
3. 무수정 왕복 검사
   - 새 원본 조각을 그대로 합성했을 때 논리 RGBA가 유지되는지 확인
   - 수정 대상이 없는 4×4 블록은 원본 바이트가 유지되는지 확인
4. 격리 편집 검사
   - 세 문구에 각각 식별 가능한 임시 단일 블록 변경을 적용
   - 변경이 해당 문구 좌표에만 나타나는지 확인
   - 우측 선택지와 다른 두 패널이 바뀌지 않는지 확인
   - 임시 편집 파일은 사용자 작업 공간과 분리하고 검사 후 정리
5. 독립·내장 사본 검사
   - 독립 `saveicon2.dds.z` 수정 확인
   - `init.bin/static_tex.dds.z` 그림 69 수정 확인
   - 두 렌더 결과가 픽셀 단위로 동일한지 확인
6. GUI 통합 검사
   - 새 편집 조각 3개를 정확히 인식
   - 독립 파일과 내장 그림을 모두 교체 목록에 포함
   - 컨테이너 및 `init.bin` 할당 공간 초과 없음
7. 생성 ISO 재추출 검사
   - 독립 파일과 내장 그림 69를 다시 추출해 한글 편집 결과 확인
   - 미편집 블록과 원본 ISO SHA-256 유지 확인

## 제외 범위

- `Yes`, `No`, `Delete` 선택지 번역 또는 디자인 변경
- 사용자가 만든 기존 지역명 이미지 변경
- 다른 추가 이미지 리소스의 좌표 재설계
- 원본 ISO 직접 수정
- 전체 512×128 텍스처의 불필요한 재인코딩

## 위험 및 대응

- 아틀라스의 문구와 배경이 같은 DXT 블록을 공유할 수 있다. 최소 4×4 경계로만
  편집하고 변경되지 않은 블록은 원본 바이트를 유지한다.
- 독립 파일과 내장 그림 69의 블록 배치가 다르면 동일 payload라고 가정하지 않고
  각각 원본 구조를 검증한 뒤 같은 논리 편집을 적용한다.
- 기존 편집 파일이 발견되면 자동으로 덮어쓰지 않고 크기·좌표 이전 필요성을 먼저
  보고한다.

## 복구 방법

- 변경은 스크립트, 매니페스트, 재생성 원본 PNG와 별도 061 테스트 ISO에만
  적용한다.
- 문제가 생기면 `save_confirmations`의 이전 매니페스트와 원본 조각을 복원하고
  원본 컨테이너를 사용한다.
- 원본 ISO는 수정하지 않는다.
