# 060. Ys VI 전체 추가 이미지 런타임 사본 동기화 계획

## 상태

- 완료 (2026-08-20)

## 문제

- 059에서는 `placename02.dds.z`의 맵 아카이브 사본 14개만 동기화했다.
- 추가 이미지 리소스 전체를 다시 조사한 결과, `placename00.dds.z`와
  `placename01.dds.z`도 다수의 맵 아카이브에 동일한 런타임 사본이 있다.
- 현재 매니페스트에는 이 27개 사본이 기록되지 않아, 향후 GUI에서 해당 지역명
  이미지를 편집해도 독립 파일만 바뀌고 게임에는 원본 일본어가 표시될 수 있다.

## 목표

- GUI에서 `place_names_00`, `place_names_01`, `place_names_02` 중 어느 이미지를
  편집하더라도 독립 파일과 해당 맵 아카이브 사본이 모두 자동 동기화되게 한다.
- 다른 추가 이미지 리소스도 확인된 독립·내장 관계에 따라 빠짐없이 반영되는지
  통합 검사한다.

## 수정 범위

1. `tools/patchdata/ys6_additional_images/manifest.json`에 다음을 추가한다.
   - `place_names_00`: 런타임 사본 14개
   - `place_names_01`: 런타임 사본 13개
2. 059에서 구현한 공통 `runtime_copies` 동기화 로직을 그대로 사용한다.
3. 매니페스트의 모든 런타임 사본 정의에 대해 경로·index·이름·flags·원본
   컨테이너 동일성을 검사한다.
4. GUI 통합 사전검사 보고서에서 편집된 리소스에 해당하는 사본 수와 교체 성공
   수를 표시한다.
5. 향후 전수 조사 재현을 위해 추가 이미지별 독립·맵 아카이브·`static_tex`
   사본 관계를 결과 문서에 정리한다.

## 검증

1. 매니페스트 검사
   - `place_names_00` 14개, `place_names_01` 13개, `place_names_02` 14개
   - 전체 맵 아카이브 런타임 사본 41개
   - 중복된 `(archive_path, index, name, flags)` 정의 없음
2. 원본 ISO 검사
   - 41개 엔트리 모두 존재
   - 각 사본이 대응 독립 원본 컨테이너와 바이트 단위로 동일
   - 모든 할당 공간이 수정 컨테이너 크기 이상
3. 격리 검사
   - `place_names_00` 편집 조각 하나를 임시 입력으로 적용해 14개 사본 동기화
   - `place_names_01` 편집 조각 하나를 임시 입력으로 적용해 13개 사본 동기화
   - 임시 편집 조각은 검사 후 제거하고 정리 내역 기록
4. 기존 사용자 편집 회귀 검사
   - `place_names_02` 편집 이미지 2개 인식
   - 기존 14개 사본 동기화 유지
5. 다른 추가 이미지 회귀 검사
   - `save_confirmations`, `item_use_confirmation`, `item_message`의 `static_tex`
     내장 사본 동기화 경로 유지
   - 맵 아카이브 사본이 없는 5개 리소스는 독립 파일만 교체
6. 통합 사전검사 및 생성 ISO 검사
   - 편집된 모든 리소스의 독립 파일과 런타임 사본 교체 수 일치
   - 생성 ISO에서 대상 컨테이너를 재추출해 컨테이너·payload·렌더 동일성 확인
   - 대사 등 기존 아카이브 변경과 겹치는 경우 누적 보존 확인
7. 원본 ISO SHA-256 유지 확인

## 제외 범위

- 사용자가 편집하지 않은 이미지의 디자인 변경
- 근거가 없는 아카이브 또는 `static_tex` 사본 추가
- 원본 ISO 직접 수정
- 대상 엔트리 외 맵 아카이브 데이터 재압축 또는 재배치

## 위험 및 대응

- 27개 사본 중 하나라도 원본이 다르면 자동 적용하지 않고 빌드를 중단한다.
- 다른 패치와 같은 아카이브를 수정할 때는 기존 `archive_cache`에 누적 적용한다.
- 격리 검사용 임시 편집 이미지는 사용자 작업 파일과 분리하고 검사 후 삭제한다.

## 복구 방법

- 변경은 매니페스트와 별도 060 테스트 ISO에만 적용한다.
- 문제가 생기면 `place_names_00`, `place_names_01`의 `runtime_copies` 정의를
  되돌리고 원본 아카이브를 사용한다.
- 원본 ISO와 사용자 편집 이미지는 수정하지 않는다.
