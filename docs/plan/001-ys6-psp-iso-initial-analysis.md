## 중간 확인 결과

- 실제 ISO 위치는 저장소 기준 `/roms/Ys VI - Napishtim no Hako (Japan).iso`이다.
- 크기: 866,254,848바이트
- SHA-256: `0133DC75EEEFB7E1864180C88E486D2EEBE9AE3D1DBFA990BEF57E28BAAE082B`
- ISO 메타데이터: `System: PSP GAME`, `Publisher: KONAMI`, 생성 시각 `2005-09-21 20:38:02`
- ISO 내부 파일은 9,291개이며, 그중 9,260개가 `PSP_GAME/USRDIR/data` 아래에 있다.
- `BOOT.BIN`은 평문 ELF이고 `EBOOT.BIN`은 `~PSP` 헤더를 가진 PSP 보호 컨테이너다.
- 대사 유력 후보는 맵별 `talk*.xso.z`, `seltalk.xso.z`, `endtalk.xso.z` 파일이다.
- `.z` 표본은 `8바이트 게임 헤더 + zlib 스트림` 구조다. 오프셋 8에서 `78 DA`가 확인됐다.
- `.z` 헤더 오프셋 4의 u32 LE 값은 표본의 비압축 크기와 일치한다.
- 이미지 자산은 `.dds.z`라는 이름을 쓰지만, 비압축 표본의 실제 매직은 `MIG.00.1PSP`로 확인되어 일반 DDS가 아닌 게임 고유/이식 자산 포맷으로 보인다.
- 대표 파일은 분석용 임시 경로 `/.work/ys6-initial`에만 추출했으며 원본 ISO는 변경하지 않았다.
- XSO 표본 5개를 분석해 `XSR\0` 바이트코드, CP932 문자열 풀 및 상대 오프셋 테이블 구조를 확인했다.
- 상세 결과는 `/docs/result/003-ys6-xso-dialogue-format-analysis.md`에 기록했다.
- XSO 대표 표본 31개를 추가 검사해 363개 문자열과 가변 길이 VM 명령 구조를 확인했다.
- 본문·화자·선택지·경로 문자열 참조 opcode 후보는 `/docs/result/005-ys6-xso-bytecode-reference-analysis.md`에 기록했다.
- XSR 대표 31개에서 무수정 `parse → rebuild` 바이트 동일성 라운드트립을 통과했다.
- 상세 결과는 `/docs/result/006-ys6-xsr-roundtrip-rebuilder.md`에 기록했다.
- `.z` 대표 32개에서 해제→레벨 9 재압축 후 컨테이너 전체 바이트 동일성을 통과했다.
- 상세 결과는 `/docs/result/007-ys6-z-recompression-roundtrip.md`에 기록했다.
- 동일 CP932 바이트 길이 대사 교체→XSR 재조립→`.z` 재압축 PoC를 통과했다.
- 대상 파일은 기존 한 섹터에 들어가지만 압축 크기가 11바이트 증가해 ISO 9660 LE/BE 논리 크기 갱신이 필요하다.
- 상세 결과는 `/docs/result/008-ys6-same-length-string-patch-poc.md`에 기록했다.
- `/patched/009-talkkebin-string-poc`의 단일 ISO 작업본에 대상 XSO를 제자리 교체하고 ISO 9660 LE/BE 크기를 갱신했다.
- 재추출·재해제·문자열 정적 검증은 통과했으나 PPSSPP 환경이 없어 인게임 표시는 미검증이다.
- 상세 결과는 `/docs/result/009-ys6-single-file-iso-patch-poc.md`에 기록했다.

## 대상

- 원본: `/roms/Ys VI - Napishtim no Hako (Japan).iso`
- 플랫폼: PSP
- 지역 및 언어: 일본판, 일본어
- 목표: 한글 패치에 앞서 대사·시스템 문자열·폰트·이미지 텍스트·압축 또는 암호화 계층의 위치와 형식을 파악한다.

## 원본 보호 원칙

- ISO는 전 과정에서 읽기 전용 입력으로 취급한다.
- ISO 내부 파일을 원본 위치에 덮어쓰지 않는다.
- 초기 조사에서는 `/patched`에 수정 ISO를 만들지 않는다.
- 추출이 필요하면 분석용 산출물만 별도 작업 경로에 만들고, 출처 ISO 경로와 해시를 문서에 기록한다.
- 원본 게임 데이터 및 대용량 추출물은 Git에 커밋하지 않는다.

## 분석 단계

### 1. 원본 식별 및 컨테이너 조사

- 파일 존재 여부, 크기, 수정 시각을 확인한다.
- SHA-256 등 식별 해시를 계산한다.
- ISO 9660/UDF 여부와 PSP 표준 디렉터리 구성을 확인한다.
- `PSP_GAME/PARAM.SFO`, `SYSDIR`, `USRDIR` 등 주요 엔트리를 목록화한다.
- 가능하면 PARAM.SFO에서 타이틀 ID, 타이틀명, 버전 정보를 읽는다.

### 2. 실행 파일 및 보호 계층 조사

- `BOOT.BIN`, `EBOOT.BIN`, PRX 모듈 존재 여부와 파일 형식을 확인한다.
- 실행 파일이 일반 ELF인지, PSP 암호화/서명 컨테이너인지 판별한다.
- 복호화가 필요하면 먼저 필요성, 사용할 도구, 생성 산출물과 법적·배포상 취급 범위를 문서화한다.
- 승인되지 않은 복호화나 실행 파일 수정은 이번 초기 조사에서 수행하지 않는다.

### 3. 파일 인벤토리 및 아카이브 후보 분류

- ISO 전체 파일 목록과 크기 분포를 작성한다.
- 확장자, 매직 바이트, 엔트로피, 반복 헤더를 기준으로 실행 파일·아카이브·스크립트·이미지·폰트·오디오·영상 후보를 분류한다.
- 확장자와 실제 포맷이 다른 파일을 별도 표시한다.
- 대형 단일 아카이브나 인덱스/데이터 쌍이 있는지 확인한다.

### 4. 일본어 텍스트 위치 조사

- Shift-JIS, UTF-8, UTF-16LE/BE 및 커스텀 2바이트 테이블 가능성을 조사한다.
- 실행 파일과 데이터 파일에서 일본어 문자열 표본을 검색한다.
- 대사, 메뉴·아이템·도움말 등 텍스트 계열을 구분한다.
- 문자열 주변의 포인터 테이블, 길이 필드, 종료자, 제어코드 후보를 기록한다.
- 이 단계에서는 텍스트를 수정하지 않는다.

### 5. 이미지·폰트 위치 조사

- GIM, TIM2, PNG 등 알려진 이미지 포맷과 독자 텍스처 후보를 찾는다.
- 이미지에 직접 그려진 일본어 UI·타이틀·메뉴 후보를 목록화한다.
- PGF 사용 여부와 게임 내장 비트맵/텍스처 폰트 후보를 확인한다.
- 폰트와 렌더러의 연결 관계는 확정 증거와 가설을 구분해 기록한다.

### 6. 압축·암호화 후보 조사

- 파일 매직, 엔트로피, 압축 전후 크기 필드 및 실행 코드의 디컴프레서 흔적을 조사한다.
- 알려진 PSP/게임별 압축 포맷과 독자 포맷 가능성을 구분한다.
- 압축 해제가 필요한 후보는 우선 표본 하나에 대해 형식과 검증 조건을 문서화한다.
- 실제 디컴프레서·복호화 도구 구현은 별도 계획과 사용자 확인 후 진행한다.

### 7. 결과 및 후속 작업 제안

- `/docs/result/001-ys6-psp-iso-initial-analysis.md`에 조사 결과를 작성한다.
- 파일 맵, 텍스트 후보, 이미지 후보, 폰트 후보, 압축·암호화 후보, 확정 사항과 미확정 가설을 구분한다.
- 다음 단계 후보를 비용과 위험도에 따라 정렬한다.
- 별도 도구가 필요하면 `/tools/scripts` 또는 `/tools`에 만들 후속 계획을 제안하되 이번 단계에서 임의 구현하지 않는다.
