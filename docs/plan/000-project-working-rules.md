# 프로젝트 작업 규칙 등록

## 상태

- 규칙 등록: 완료
- 사용자 검토: 대기
- 향후 작업 적용: 사용자 검토 후 모든 작업에 적용

## 목적

한글 패치 도구와 스크립트의 위치, 개발 언어, 작업 승인 절차, 원본 및 수정 ROM의 취급 방식을 저장소 차원의 상시 규칙으로 고정한다.

## 등록한 규칙

1. 사용자용 GUI 한글 패치 도구는 `/tools`에 작성한다.
2. 비GUI 처리 스크립트는 `/tools/scripts`에 작성한다.
3. GUI는 가급적 Python으로 작성한다.
4. Node.js 스크립트는 `/tools/scripts/nodejs`에 작성한다.
5. 개발 언어는 가능한 한 통일하되 필요시 다른 언어를 사용할 수 있다.
6. 모든 작업은 계획 작성 → 사용자 확인 → 처리 → 결과 문서 작성 순서로 진행한다.
7. 계획 문서는 `/docs/plan`, 결과 문서는 `/docs/result`에서 관리한다.
8. 원본 ROM은 가급적 직접 수정하지 않는다.
9. 수정 ROM을 불필요하게 중복 생성하지 않으며, 이슈 종료 시 테스트 산출물을 정리할 수 있게 기록한다.
10. 수정된 ROM은 `/patched` 아래에서 이슈별로 관리한다.

## 저장소 반영

- 상시 지침: `/AGENTS.md`
- 본 등록 문서: `/docs/plan/000-project-working-rules.md`

## 사용자 확인 항목

- 위 규칙의 해석과 문구가 의도에 맞는지 확인한다.
- 확인 후 본 문서를 완료 처리하여 `/docs/result`로 이동하거나 결과 문서를 별도로 작성한다.
