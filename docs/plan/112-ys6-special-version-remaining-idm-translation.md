# 112. Ys VI SPECIAL VERSION 잔여 IDM 문구 분류 및 번역 계획

상태: 완료(색상 행동 설명 및 한글 출력 사용자 실기 확인)

## 배경

- 111번은 IDM 전체 6,341개 문자열 중 기존 번역 원본과 안전하게 대응된 4,127개를 적용했다.
- 미적용 문자열은 2,214개이며, 이 가운데 일본어 본문이 남은 항목은 2,029개다.
- 잔여 일본어 중 약 1,298개는 기존 일반판 XSO 번역 데이터에 동일 원문이 없는 SPECIAL VERSION 전용 문구다.
- 나머지 약 731개는 기존 번역 데이터에 동일 원문이 있지만 중복 위치 또는 문맥 모호성 때문에 자동 이식에서 제외됐다.
- 사용자가 확인한 `<color:0xffacdae8>` 행동 보조 설명은 SPECIAL VERSION IDM에만 존재하므로 109·111번의 기존 번역 이식 대상에 포함되지 않았다.

## 목적

- 잔여 일본어 2,029개를 실제 표시 가능성 및 용도에 따라 분류한다.
- 기존 번역을 안전하게 재사용할 수 있는 중복·모호 항목을 최대한 자동 해소한다.
- SPECIAL VERSION 전용 행동 설명, 일반 대사 및 선택지를 한글로 번역한다.
- 번역하지 않아도 되는 식별자, 미사용 문구 및 말줄임표 전용 항목을 명시적으로 제외한다.
- 기존 revision 4 매핑 946자를 append-only로 보존하고 필요한 신규 한글만 뒤에 추가한다.
- 번역 결과를 독립 IDM과 모든 런타임 복사본에 적용한 시험 ISO를 생성한다.

## 1. 잔여 IDM 작업공간 생성

- 111번 최종 적용 키 `(target_iso_path, target_flat_index)`를 기준으로 적용 완료 4,127개를 제외한다.
- 남은 2,214개에서 일본어 가나·한자 본문이 있는 2,029개를 잔여 작업공간으로 추출한다.
- 각 항목에 다음 정보를 기록한다.
  - IDM 경로, map ID, flat/record/string index 및 record ID
  - 일본어 원문, 원문 HEX 및 SHA-256
  - 색상·ruby·개행 등 제어 태그
  - 기존 XSO 번역 데이터의 동일 원문 후보와 역할
  - 중복 IDM 위치와 동일 payload 관계
  - 분류, 번역, 상태 및 검토 메모
- 작업공간은 경로·인덱스·원문 해시를 안정 키로 사용해 이후 재생성해도 사용자 번역을 보존한다.

## 2. 표시 용도 분류

- 잔여 항목을 다음 범주로 분류한다.
  - `action_narration`: 주인공이나 등장인물의 행동을 설명하는 색상 문구
  - `dialogue`: 일반 대사
  - `choice`: 선택지 및 선택 안내
  - `system_prompt`: IDM 내부 안내·확인 문구
  - `resource_or_identifier`: 리소스명, 이벤트명 및 내부 식별자
  - `punctuation_only`: 말줄임표·기호만 있는 문구
  - `duplicate`: 동일 대상 또는 동일 문맥의 중복 문구
  - `unused_or_unknown`: 참조 여부가 없거나 용도를 확정하지 못한 문구
- `<color:0xffacdae8>`로 시작하며 행동 서술형인 문장은 우선 `action_narration`으로 분류한다.
- 일본어 본문처럼 보여도 이벤트명·디버그명으로 판단되는 항목은 자동 번역하지 않고 별도 목록에 둔다.
- 분류별 개수와 초반 맵 표본을 보고서 및 CSV로 출력한다.

## 3. 기존 번역 재사용

- 기존 XSO 작업공간에서 동일 원문 후보가 있는 약 731개를 다시 분석한다.
- 후보 번역이 모두 동일하면 IDM 위치가 여러 개여도 동일 번역을 안전 재사용한다.
- 후보 번역이 다르면 인접 IDM 문자열, map ID, record ID, 기존 XSO 경로와 역할로 문맥을 비교한다.
- 문맥으로 하나를 확정할 수 없는 항목은 임의 선택하지 않고 `ambiguous_review`로 유지한다.
- 재사용 번역의 원본 경로·인덱스와 결정 근거를 각 행에 기록한다.

## 4. SPECIAL VERSION 전용 문구 번역

- 기존 번역 후보가 없는 약 1,298개 중 실제 표시 대상으로 분류된 항목을 번역한다.
- 행동 설명은 현재 게임 문체에 맞춰 다음 원칙을 사용한다.
  - 주어 `아돌`과 목적어를 원문대로 보존한다.
  - 과거 서술형 `~했다`, `~에게 전했다`, `~까지 데려갔다`를 기본으로 한다.
  - `<color:...>` 태그, 선두 전각 공백 및 개행 구조는 출력 형식을 깨지 않는 범위에서 보존한다.
- 일반 대사와 선택지는 기존 용어집 및 현재 번역 문체를 따른다.
- 일본어 ruby 태그는 한글 독음이 필요 없으므로 제거하되 본문 의미는 유지한다.
- 말줄임표·기호만 있는 항목은 별도 번역 없이 원문 바이트를 유지한다.
- 동일 일본어 원문은 같은 문맥이면 같은 번역으로 통일하고, 문맥상 의미가 다른 경우만 구분한다.

## 5. 번역 검증

- 빈 번역, 일본어 잔존, 미지원 태그 및 잘못된 개행 escape를 검사한다.
- 원문과 번역의 색상 태그 수와 종료 구조를 비교한다.
- 행동 설명과 선택지에 대화 화자 표기나 불필요한 따옴표가 추가되지 않았는지 확인한다.
- 동일 대상 문자열에 서로 다른 번역이 배정되는 shared payload conflict를 검사한다.
- 문장 길이가 기존 표시 영역을 과도하게 넘는 후보를 별도 보고한다.
- 자동 번역 대상과 의도적 제외 대상을 구분해 최종 일본어 잔존 수를 보고한다.

## 6. append-only 폰트 매핑 확장

- 111번 mapping revision 4의 946개 행을 순서·코드·폰트 인덱스까지 그대로 보존한다.
- 신규 번역에 필요한 한글 중 revision 4에 없는 문자만 Unicode 순으로 append한다.
- 신규 코드는 110·111번에서 검증한 Shift-JIS 사용자 정의 영역의 다음 사용 가능 코드부터 배정한다.
- 신규 폰트 인덱스는 111번 최종 테이블 2,286개 뒤에서 연속 배정한다.
- BOOT/EBOOT은 109번 기반 실행 파일에서 revision 4의 512자와 112번 신규 문자를 같은 확장 테이블에 재생성한다.
- 프로그램 헤더 index 2의 신규 `PT_LOAD`, index 3의 PSP relocation 및 세 검색 경로 구조는 유지한다.
- mapping revision은 5로 올리고 기존 946개 선두가 완전히 동일한지 검사한다.

## 7. IDM 용량 사전 검증

- 111번 4,127개 번역과 112번 신규·재사용 번역을 합친 최종 상태로 모든 IDM을 재구성한다.
- standalone extent와 모든 아카이브 엔트리 할당량을 각각 검사한다.
- `s_4010`은 현재 4,087/4,096바이트로 여유가 9바이트뿐이므로 번역이 추가되는지 별도 확인한다.
- 할당량 초과가 발생하면 다음 순서로 처리한다.
  1. 의미를 유지하는 번역 축약 후보 제시
  2. 사용자가 번역을 조정한 뒤 재검증
  3. 축약으로 해결할 수 없는 경우에만 standalone 또는 아카이브 신규 extent·구조 확장 계획 추가
- 번역을 임의로 절단하거나 초과 항목을 조용히 제외하지 않는다.

## 8. 전체 시험 ISO 생성

- 111번 ISO는 사용자 실기 비교 기준으로 보존한다.
- 재현성을 위해 검증된 109번 ISO와 revision 3 매핑에서 최종 revision 5 폰트 및 전체 IDM을 새로 빌드한다.
- 독립 IDM과 `runtime-map.json`의 모든 아카이브 복사본을 함께 갱신한다.
- 확장 BOOT/EBOOT은 ISO 끝의 신규 extent에 배치하고 directory record와 volume space size를 갱신한다.
- 출력은 `patched/112-special-version-remaining-idm-translation`에 별도 생성한다.

## 9. 검증

- revision 4의 기존 매핑 946개가 revision 5 선두에서 바이트 및 JSON 행 단위로 동일한지 확인한다.
- 신규 코드·폰트 인덱스·문자가 모두 고유한지 검사한다.
- 프로그램 헤더 순서와 세 폰트 주소 재배치 결과 `0x360000`을 확인한다.
- 최종 폰트 레코드 수와 세 검색 상한이 일치하는지 확인한다.
- 적용 대상 번역 바이트를 재추출 IDM에서 전수 비교한다.
- 독립 IDM과 모든 런타임 복사본을 전수 비교한다.
- 기존 111번 번역 중 사용자 수정 대상이 아닌 바이트가 유지되는지 회귀 검사한다.
- 모든 수정 ISO 파일을 재추출해 작업본 SHA-256과 비교한다.

## 10. 사용자 실기 확인

- 초반에 확인 가능한 색상 행동 설명 문구를 우선 테스트 지점으로 선정한다.
- 일반 대사, 행동 설명, 선택지에서 한글이 각각 정상 표시되는지 확인한다.
- 색상, 들여쓰기, 개행 및 대화 진행이 정상인지 확인한다.
- 기존 111번 대사와 시스템 메시지가 사라지거나 깨지지 않는지 확인한다.
- 저장, 불러오기 및 맵 이동을 확인한다.

## 제외 범위

- IDM 외 XSO 신규 번역
- 인물·몬스터명, 아이템 및 별도 시스템 메시지 이식
- 이미지, 영상, XMB 및 아날로그 스틱 기능의 SPECIAL VERSION 이식
- GUI에 SPECIAL VERSION 전체 패치 옵션 추가
- 실제 표시 여부를 확정하지 못한 내부·디버그 식별자의 무조건 번역

## 위험 및 중단 조건

- revision 4의 기존 946개 매핑이 하나라도 바뀌면 ISO를 생성하지 않는다.
- 제어 태그 구조가 불명확한 항목은 자동 번역하지 않고 검토 대상으로 남긴다.
- shared payload에 서로 다른 번역이 생기면 충돌을 해결하기 전까지 해당 ISO를 생성하지 않는다.
- 하나라도 IDM 또는 아카이브 할당량을 넘으면 사용자 확인 없이 구조를 확장하지 않는다.
- 행동 설명 번역이 기존 색상·들여쓰기 표시를 손상시킬 가능성이 있으면 소수 표본 ISO로 먼저 검증한다.

## 완료 기준

- 잔여 일본어 2,029개의 분류와 처리 상태가 모두 기록된다.
- 실제 표시 대상으로 확정된 행동 설명·일반 대사·선택지가 번역된다.
- 기존 번역 재사용 항목은 결정 근거와 출처가 기록된다.
- mapping revision 5가 기존 946자를 append-only로 보존한다.
- 최종 IDM과 모든 런타임 복사본이 용량 및 재추출 검증을 통과한다.
- 사용자가 초반 행동 설명과 기존 대사가 함께 정상 표시되는 것을 확인할 수 있다.
