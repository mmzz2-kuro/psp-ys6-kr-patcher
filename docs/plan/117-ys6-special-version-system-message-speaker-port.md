# 117. Ys VI SPECIAL VERSION 시스템 메시지·익명 화자명 이식 계획

상태: 완료

## 2026-08-27 범위 변경

- 익명 화자명은 사용자의 요청에 따라 이번 단계의 실제 적용 범위에서 보류한다.
- SPECIAL VERSION ISO의 IDM, `castinfo.dat.z` 및 원시 바이트 조사에서는 `男の声`, `娘の声` 등의 독립 문자열이 발견되지 않았다. 실제 표시 장면과 위치가 확보되면 별도 후속 계획에서 런타임 표시 경로를 조사한다.
- 시스템 메시지 332개의 전용 작업공간을 생성했고, 기존 EUC-JP 변환으로 안전한 승인 번역 38개를 1차 적용했다.
- 사용자가 키 설정 화면에서 `공격`, `도구사용`, `마법사용`, `되돌리기`, `뒤로`의 정상 출력을 확인했다.
- 기존 글리프 순서를 바꾸지 않고 사용하지 않는 레거시 글리프 코드에 시스템 전용 한글 비트맵을 연결하는 별칭 시험을 수행했다.
- 시험 별칭 `점`, `검`, `좌`를 사용한 `점프`, `검 교체 (좌)`, `검 교체 (우)`가 실제 기기에서 정상 출력됨을 사용자가 확인했다.
- 이후 범위는 이 검증된 별칭 방식을 남은 승인 시스템 메시지에 확장하는 것으로 변경한다.

### 변경된 적용 원칙

- 일반 대사·인물명·아이템 및 기존 한글 매핑의 문자, 게임 코드, 폰트 인덱스는 변경하지 않는다.
- 시스템 메시지에만 별도 별칭 매핑을 사용한다.
- 별칭 대상 레거시 코드는 다음 자료에서 실제 사용하는 문자를 제외한 뒤 선정한다.
  - 아직 일본어로 유지할 SPECIAL 시스템 메시지
  - SPECIAL IDM 원문과 미번역 문자열
  - SPECIAL 인물·몬스터 및 아이템 원문
  - 실행 파일의 메뉴·도움말·저장 관련 일본어 후보
- 같은 레거시 코드가 두 한글에 배정되거나 기존 정식 한글 매핑과 충돌하면 빌드를 중단한다.
- 별칭 확장 후 승인 메시지 138개 대응 위치를 다시 계산하고, 길이·형식 토큰·원문 바이트 검증을 통과한 항목만 `override`로 적용한다.
- 신규 한글 글리프가 필요하면 정식 매핑 끝에 append하지 않고 시스템 별칭 자산 안에서만 관리한다. 대사나 세이브 문자열에는 별칭 코드를 사용하지 않는다.
- 별칭으로 대체되는 일본어 글리프와 제외 근거를 감사 보고서에 모두 기록한다.

## 배경

- 116번에서 SPECIAL VERSION의 인물·몬스터명 70개와 아이템 72개를 이식했다.
- `男の声`, `女の声`, `女性の声`, `少女の声`처럼 인물 ID가 없는 익명 화자명은 116번 인물명 작업공간에 포함되지 않았고 현재 SPECIAL VERSION 번역 데이터에도 독립 화자명으로 등록되어 있지 않다.
- 115번 조사에서 SPECIAL VERSION 실행 파일의 시스템 메시지 후보 332개와 일반판 승인 번역 161개의 대응 관계를 확보했다.
- 시스템 메시지는 실행 파일에 EUC-JP로 저장된 뒤 런타임에 Shift-JIS로 변환되므로, 기존 사용자 정의 한글 코드까지 안전하게 도달시키는 변환 경로 확장이 필요하다.

## 목적

- SPECIAL VERSION의 익명 화자명 저장·표시 구조를 조사하되 실제 적용은 보류한다.
- 115번에서 확인한 시스템 메시지의 변환 경로를 확장하고 안전하게 이식 가능한 승인 번역을 적용한다.
- 중복 원문, 고정 길이, 형식 토큰 및 BOOT/EBOOT 동기화를 사전 검증한다.
- GUI의 사전 검증과 ISO 패치 생성이 동일한 117번 작업공간을 사용하도록 통합한다.

## 작업 범위

### 1. 익명 화자명 전수 조사 및 적용 보류

- 일반판 대화 작업공간에서 `声`가 포함된 화자명을 추출한다.
- SPECIAL VERSION의 IDM 원문, 화자명 필드 및 표시 경로와 대조한다.
- `男の声`, `女の声`, `女性の声`, `少女の声`, `謎の声` 등 실제 존재하는 항목을 원문별로 목록화한다.
- 대사 본문에 포함된 `女性の声` 같은 일반 문장과 독립 화자명은 구분한다.
- 같은 원문이 여러 위치에서 다른 의미로 사용되면 자동 공유하지 않고 위치별 검수 대상으로 남긴다.
- 조사 결과만 기록하고 이번 117번 ISO에는 적용하지 않는다.

### 2. 익명 화자명 조사 자료 작성

- 일반판에서 승인된 번역이 있으면 원문과 문맥이 일치하는 항목만 재사용한다.
- 미승인 또는 SPECIAL 전용 화자명은 별도 검수 상태로 기록한다.
- 실제 표시 위치가 확인될 때까지 번역 패치와 신규 글리프 추가는 수행하지 않는다.
- 기존 글리프의 코드와 순서는 변경하지 않아 세이브 호환성을 유지한다.

### 3. 시스템 메시지 변환 경로 분석 및 최소 시험

- SPECIAL VERSION의 EUC-JP→Shift-JIS 변환 테이블과 호출 경로를 식별한다.
- 기존 CP932 문자와 revision 7 사용자 정의 한글 코드가 함께 동작하는 확장 방식을 설계한다.
- 시스템 메시지 한두 개만 바꾸는 최소 시험 데이터를 만들어 다음을 확인한다.
  - 한글 글리프가 정상 표시되는지
  - 주변 실행 코드와 문자열이 손상되지 않는지
  - BOOT.BIN과 EBOOT.BIN에서 동일하게 적용되는지
- 실행 코드 변경이 불안정하거나 코드 공간이 부족하면 전체 적용을 중단하고 분석 결과와 대안을 기록한다.
- 최소 시험 결과, 실행 코드 자체를 변경하지 않고 레거시 글리프 코드에 시스템 전용 한글 비트맵을 연결하는 별칭 방식이 실기에서 정상 동작했다.

### 3-1. 시스템 전용 글리프 별칭 전체 확장

- 보류된 승인 메시지에서 현재 EUC-JP 경로로 표현할 수 없는 한글을 전수 집계한다.
- 일본어 유지 영역에서 사용하지 않는 레거시 코드와 폰트 레코드를 필요한 수만큼 선정한다.
- 각 별칭에 한글, EUC-JP 저장 바이트, 런타임 Shift-JIS 코드, 레거시 폰트 레코드 및 교체되는 일본어 문자를 기록한다.
- BOOT.BIN과 EBOOT.BIN의 확장 폰트 복사본에 같은 비트맵을 적용한다.
- 별칭 매핑은 시스템 메시지 인코더에만 추가하며 공용 `hangul-mapping.json` revision과 순서는 유지한다.
- 전체 적용 전에 별칭 코드 충돌, 폰트 레코드 충돌 및 일본어 잔존 문자열 사용 여부를 감사한다.

### 4. 시스템 메시지 작업공간 확정

- 115번 대응표의 승인 번역 161개를 기준으로 정확 대응, 중복 대응, 원문 변경 항목을 재분류한다.
- 정확 대응 항목은 고정 길이와 형식 토큰 검증 후 적용 대상으로 확정한다.
- 저장·불러오기처럼 SPECIAL VERSION에서 문구가 변경된 항목은 자동 적용하지 않고 별도 검수 목록으로 만든다.
- SPECIAL 전용 후보 146개는 미번역 상태의 작업공간으로 남겨 후속 번역이 가능하게 한다.
- 별칭 확장으로 인코딩 가능해진 승인 메시지는 다시 검증하여 적용 수를 확정한다.

### 5. 패치 빌더와 GUI 통합

- SPECIAL VERSION 공용 빌더에 익명 화자명 및 시스템 메시지 적용 단계를 추가한다.
- GUI 사전 검증에서 적용 수, 제외 수, 충돌 수, 길이 초과 및 형식 토큰 오류를 표시한다.
- GUI의 사전 검증과 패치 생성이 같은 설정·작업공간·글리프 매핑을 사용하게 한다.
- BOOT.BIN과 EBOOT.BIN은 항상 동일한 번역 및 코드 변경 결과로 갱신한다.

### 6. 검증 및 테스트 ISO

- 원본 SPECIAL VERSION ISO는 읽기 전용 입력으로 사용한다.
- 무수정 왕복, 실행 파일 범위, 문자열 경계, 형식 토큰, 글리프 중복 및 기존 매핑 불변을 검사한다.
- 기존 IDM 6,156개와 116번 인물·아이템 데이터가 회귀하지 않는지 재검증한다.
- 성공 시 `/patched/117-ys6-special-version-system-message-speaker-port`에 테스트 ISO를 생성한다.

## 안전 조건과 중단 기준

- 원본 ISO는 직접 수정하지 않는다.
- 기존 한글 글리프의 문자·게임 코드·폰트 인덱스는 변경하지 않는다.
- 실행 코드 수정 위치와 참조 관계가 확정되지 않으면 추정 패치를 적용하지 않는다.
- 고정 길이 초과, 형식 토큰 불일치 또는 중복 원문 충돌이 있으면 해당 항목을 제외한다.
- BOOT.BIN과 EBOOT.BIN의 대상 바이트가 예상 원문과 다르면 빌드를 중단한다.
- 최소 시험에서 기존 대사·시스템 표시 회귀가 발견되면 전체 시스템 메시지 적용을 진행하지 않는다.

## 완료 기준

- 익명 화자명 조사 결과와 적용 보류 사유가 기록된다.
- 시스템 메시지 별칭 방식이 최소 시험과 전체 정적 검증을 통과한다.
- 적용 대상 시스템 메시지의 길이·토큰·중복 충돌 검증이 통과한다.
- GUI 사전 검증과 ISO 빌드가 같은 결과를 사용한다.
- 테스트 ISO와 결과 문서에 적용 수, 제외 항목, 검증 결과 및 실기 확인 항목이 기록된다.
