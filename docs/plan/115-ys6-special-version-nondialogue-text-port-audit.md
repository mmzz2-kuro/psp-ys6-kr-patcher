# 115. Ys VI SPECIAL VERSION 비대사 텍스트 이식 조사 계획

상태: 완료

## 배경

- SPECIAL VERSION(`ULJM-05155`)에는 114번 기준 IDM 대사·행동 설명 6,156개와 한글 폰트 revision 6이 적용돼 있다.
- 일반판(`ULJM-05009`)에서 완성한 시스템 메시지, 인물·몬스터명, 아이템명·설명은 아직 SPECIAL VERSION GUI 프로필에서 적용 수 0건으로 표시된다.
- 두 판본은 실행 파일과 일부 데이터 배치가 다르므로 일반판 오프셋이나 파일을 그대로 복사할 수 없다.
- 이미지·영상 자산보다 먼저 비대사 텍스트의 구조와 번역 재사용 범위를 확정하면 SPECIAL VERSION의 남은 일본어 표시 영역을 체계적으로 줄일 수 있다.

## 목적

- SPECIAL VERSION에서 시스템 메시지, 인물·몬스터명, 아이템명·설명의 실제 저장 위치와 런타임 복사본을 식별한다.
- 일반판 번역 작업공간과 원문·레코드 구조를 비교해 자동 이식, 검토 이식, 신규 번역 대상을 수치화한다.
- 고정 길이, 인코딩, 형식 토큰 및 폰트 요구량을 조사해 안전한 후속 적용 계획을 제시한다.
- 이번 115번은 읽기 전용 조사와 무수정 왕복 검증까지만 수행하며 ISO와 배포 패치 데이터는 변경하지 않는다.

## 조사 대상

- 일반판 원본: `roms/Ys VI - Napishtim no Hako (Japan).iso`
- SPECIAL VERSION 원본: `roms/Ys 6 - the ark of napishtim [J].iso`
- 일반판 번역 작업공간:
  - `tools/config/system-messages.json`
  - 인물·몬스터명 작업공간 및 `castinfo.dat` 관련 자료
  - `tools/config/item-translations.json`
- SPECIAL VERSION 실행 파일과 `data/misc`, `data/arc/init.bin` 및 대응 후보 리소스
- SPECIAL VERSION revision 6 매핑과 2,305개 확장 폰트 구성

## 1. 리소스 인벤토리와 런타임 경로 확인

- 두 ISO에서 `castinfo.dat`, `invinfo.dat`, `init.bin`과 이름·설명 후보 파일을 추출하지 않고 직접 읽어 크기, 해시 및 아카이브 엔트리를 기록한다.
- 독립 파일과 `init.bin` 내부 복사본이 실제로 동일한지 판정한다.
- SPECIAL VERSION에서 파일명이나 배치가 달라진 경우 레코드 크기, 헤더, 원문 시그니처로 대응 후보를 찾는다.
- 독립 파일과 런타임 복사본 중 어느 쪽을 함께 교체해야 하는지 매핑한다.

## 2. 인물·몬스터명 구조 비교

- 일반판과 SPECIAL VERSION의 `castinfo.dat` 헤더, 레코드 수, 레코드 크기, 이름 영역과 메타데이터 경계를 비교한다.
- 인물 및 `CAST_Mxxx` 몬스터 레코드를 ID, 원문 이름, 주변 레코드와 구조 해시로 대응시킨다.
- 다음 범주로 구분한다.
  - ID·원문·구조가 모두 일치해 자동 이식 가능
  - ID는 같지만 원문 또는 구조가 달라 수동 검토 필요
  - SPECIAL VERSION에만 있거나 일반판에만 존재
- 고정 길이 영역을 넘는 번역은 절단하지 않고 초과 목록으로 기록한다.

## 3. 아이템명·설명 구조 비교

- 048번에서 확정한 일반판 `invinfo.dat` 경계를 기준으로 SPECIAL VERSION의 헤더, 레코드 수, 184바이트 레코드 여부와 필드 배치를 독립적으로 다시 검증한다.
- 아이템 ID, 일본어 이름·설명, 가격·능력치 등 비문자 메타데이터를 비교한다.
- 일반판의 승인 번역을 다음 조건에서만 자동 대응한다.
  - 아이템 ID와 원문 이름·설명이 일치
  - 이름·설명 영역 및 종료 규칙이 동일
  - 비문자 메타데이터를 보존할 수 있음
- 이름과 설명의 인코딩 후 길이, 줄바꿈 변환 및 필요한 신규 글리프를 보고한다.

## 4. 시스템 메시지 탐색

- SPECIAL VERSION `BOOT.BIN`과 `EBOOT.BIN`의 데이터 영역에서 EUC-JP 널 종료 문자열을 추출한다.
- 내부 CR/LF/TAB, 짧은 메뉴 문자열, 저장·불러오기 메시지와 `%lu` 같은 형식 토큰을 포함해 일반판 318개 작업공간과 비교한다.
- 일반판의 고정 오프셋은 사용하지 않고 다음 근거를 조합해 대응한다.
  - 원문 원시 바이트 일치
  - 인접 문자열 순서와 주변 바이트 시그니처
  - 할당 길이 및 실행 파일 내 참조 위치
- 같은 원문이 여러 위치에 있으면 임의 병합하지 않고 각 SPECIAL 오프셋을 별도 레코드로 유지한다.
- BOOT/EBOOT 중 실제 부팅 시 사용되는 양쪽 결과를 동일하게 만들 수 있는지 확인한다.

## 5. 번역 재사용 및 충돌 분류

- 일반판에서 승인된 상태만 이식 후보로 삼되 기존 상태값 자체를 SPECIAL 리소스에 그대로 가정하지 않는다.
- 각 후보를 다음으로 분류한다.
  - `exact`: 원문·구조·필드 경계가 일치
  - `context_match`: 원문과 문맥은 같지만 구조나 할당 길이가 다름
  - `conflict`: 같은 SPECIAL 대상에 서로 다른 번역이 대응
  - `special_only`: SPECIAL VERSION 전용 신규 원문
  - `unmatched`: 안전한 대응 근거 부족
- 중복 원문은 ID, 주변 레코드와 런타임 위치를 이용해 잘못된 공유 번역을 차단한다.

## 6. 인코딩·폰트·용량 사전 검증

- SPECIAL revision 6 매핑으로 모든 자동 이식 후보를 인코딩해 누락 한글과 특수문자를 집계한다.
- 신규 글리프가 필요하면 필요한 문자 수와 다음 사용자 정의 코드·확장 인덱스 범위를 제시하되 이번 단계에서 매핑을 변경하지 않는다.
- 시스템 메시지와 고정 길이 이름·설명의 할당 공간 초과를 항목별로 기록한다.
- printf 형식 토큰, 개행, 탭 및 제어 바이트가 번역에서 보존되는지 검사한다.

## 7. 무수정 왕복 및 패치 가능성 판정

- 식별한 SPECIAL VERSION 리소스를 파싱 후 번역을 넣지 않고 재구성해 원본과 바이트 단위로 비교한다.
- 아카이브 복사본은 파싱·재삽입 후 비대상 엔트리가 보존되는지 확인한다.
- 실행 파일 시스템 메시지는 메모리상 시험 데이터에서만 길이·해시 검사를 수행하며 원본 또는 테스트 ISO에 쓰지 않는다.
- 항목군별로 실제 적용 단계의 난이도와 권장 순서를 결정한다.

## 제외 범위

- SPECIAL VERSION ISO 또는 배포 패치 데이터 변경
- 번역 상태 일괄 변경이나 신규 번역 작성
- 폰트 매핑 revision 증가
- 옵션 메뉴·추가 이미지, 엔딩 영상, XMB 이미지 이식
- 아날로그 스틱 기능 이식
- 대사 전체 실기 검수

## 안전 조건과 중단 기준

- 두 원본 ISO는 읽기 전용으로 사용한다.
- 일반판 오프셋이나 전체 리소스 파일을 SPECIAL VERSION에 그대로 복사하지 않는다.
- 메타데이터 경계가 불명확한 레코드는 자동 이식 후보에서 제외한다.
- 동일 대상에 번역 충돌이 있으면 임의 선택하지 않는다.
- 형식 토큰 또는 고정 길이 제약을 만족하지 못하면 적용 가능으로 판정하지 않는다.
- 조사 중 실제 실행 코드 패치나 리소스 확장이 필요하다고 확인되면 별도 후속 계획으로 분리한다.

## 완료 기준

- SPECIAL VERSION의 인물·몬스터명, 아이템 및 시스템 메시지 저장 구조와 런타임 경로가 식별된다.
- 일반판 승인 번역의 자동 이식 가능 수, 검토 필요 수, 충돌 및 신규 항목 수가 제시된다.
- 모든 자동 이식 후보의 인코딩, 글리프, 형식 토큰과 공간 제약이 검증된다.
- 무수정 왕복 검증이 통과하거나 실패 원인이 항목별로 기록된다.
- 안전한 실제 적용 범위와 다음 계획의 작업 순서가 확정된다.
