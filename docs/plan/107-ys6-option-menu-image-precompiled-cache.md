# 107. Ys VI 옵션 메뉴 이미지 사전 컴파일 캐시 전환 계획

상태: 완료

## 목적

- `ys6_option_menu` 이미지도 `ys6_additional_images`와 같은 사전 컴파일 캐시 방식으로 처리한다.
- 수정 PNG가 바뀔 때만 DXT1 재조합과 압축을 수행하고, 일반 사전 검증 및 ISO 빌드에서는 검증된 캐시를 즉시 사용한다.
- GUI의 기존 `이미지 캐시 갱신` 버튼 한 번으로 옵션 메뉴와 추가 이미지 캐시를 함께 최신 상태로 만든다.

## 현재 구조

- 옵션 메뉴는 빌드할 때마다 다음 작업을 반복한다.
  - 9개 수정 PNG 검증
  - 256×256 DXT1 아틀라스 재조합
  - `static_tex.dds.z` 압축
  - 독립 파일과 `init.bin` 내부 복사본 교체
- 추가 이미지는 `precompiled/manifest.json`과 컨테이너 캐시를 사용하며, 수정 이미지와 원본·manifest 해시가 같으면 재압축하지 않는다.

## 변경 방향

### 1. 옵션 메뉴 전용 캐시

- `tools/patchdata/ys6_option_menu/precompiled` 아래에 다음 파일을 생성한다.
  - 사전 컴파일된 `static_tex.dds.z`
  - 캐시 manifest
- 캐시 identity에는 다음 값을 포함한다.
  - 지원 원본 ISO SHA-256
  - 원본 독립 `static_tex.dds.z` SHA-256
  - 해제된 원본 payload SHA-256
  - 옵션 메뉴 manifest 정의 SHA-256
  - 적용되는 9개 수정 PNG의 상대 경로, 크기와 SHA-256
  - DXT1 조합·압축 방식의 캐시 스키마 또는 알고리즘 버전

### 2. 증분 갱신

- identity가 모두 같고 캐시 파일 해시가 맞으면 기존 캐시를 재사용한다.
- 수정 PNG, manifest, 원본 또는 알고리즘 버전 중 하나라도 달라지면 옵션 메뉴 캐시 한 건만 다시 생성한다.
- 새 캐시 검증이 모두 끝난 뒤 기존 캐시를 원자적으로 교체한다.
- 갱신 실패 시 기존 정상 캐시를 보존한다.

### 3. 빌더 적용

- 옵션 메뉴 적용이 선택된 경우 사전 검증과 ISO 빌드 모두 캐시 존재 여부와 identity를 검증한다.
- 유효한 캐시가 있으면 빌드 중 `compose_option_menu`와 재압축을 반복하지 않고 캐시 컨테이너를 사용한다.
- 캐시가 없거나 오래됐으면 잘못된 결과로 계속 진행하지 않고 GUI에서 캐시 갱신을 안내한다.
- 캐시 컨테이너를 독립 `static_tex.dds.z`와 `init.bin` 내부 복사본 양쪽에 동일하게 적용한다.
- 옵션 메뉴 적용 체크를 해제하면 캐시 검증과 적용을 모두 건너뛴다.

### 4. GUI 통합

- 현재 `이미지 캐시 갱신` 버튼에서 다음 순서로 처리한다.
  1. 옵션 메뉴 이미지 캐시 상태 확인 및 필요 시 갱신
  2. 추가 이미지 리소스별 증분 캐시 갱신
- 상태 표시에는 옵션 메뉴와 추가 이미지 캐시 상태를 구분해 표시한다.
- 진행 로그에는 재사용·재생성 대상과 소요 시간을 각각 기록한다.
- 두 캐시가 모두 최신이면 재압축 없이 즉시 완료로 표시한다.

- `tools/scripts/ys6_option_menu_image.py`
- `tools/scripts/ys6_integrated_build.py`
- `tools/ys6_dialogue_viewer.py`

## 검증

1. Python 문법 검사를 수행한다.
2. 최초 캐시 생성 후 payload와 컨테이너 왕복 검증을 수행한다.
3. 변경 없는 상태에서 다시 갱신해 재사용되고 파일이 바뀌지 않는지 확인한다.
4. 수정 PNG 한 장의 복사본을 격리 작업공간에서 변경해 옵션 메뉴 캐시만 오래된 것으로 판정되는지 확인한다.
5. 갱신 후 새 캐시만 교체되고 추가 이미지 캐시는 재압축되지 않는지 확인한다.
6. 캐시 파일 변조와 manifest 불일치를 차단하는지 확인한다.
7. 옵션 메뉴 적용·해제 양쪽 사전 검증을 수행한다.
8. 캐시 사용 빌드의 `static_tex.dds.z`가 기존 직접 생성 결과와 payload 및 화면 블록 기준으로 동일한지 확인한다.
9. 독립 파일과 `init.bin` 내부 복사본이 동일한 캐시 컨테이너를 사용하는지 확인한다.

## 산출물

- 옵션 메뉴 사전 컴파일 캐시 및 manifest
- 캐시 생성·상태 검사 스크립트
- GUI 통합 변경
- 검증 자료: `tools/patchdata/work/current/107-option-menu-cache`
- 결과 문서: `docs/result/107-ys6-option-menu-image-precompiled-cache.md`

## 안전 조건

- 원본 ISO는 읽기 전용으로 사용한다.
- 새 캐시 전체 검증 전에는 기존 캐시를 교체하지 않는다.
- 캐시가 오래됐을 때 이전 이미지를 조용히 적용하지 않는다.
- 사용자 수정 PNG는 변경하지 않는다.
- 검증에 전체 ISO가 필요하지 않으면 새 테스트 ROM을 만들지 않는다.

## 완료 기준

- 옵션 메뉴 수정 PNG가 바뀐 경우에만 캐시가 재생성된다.
- 일반 사전 검증과 ISO 빌드는 검증된 옵션 메뉴 캐시를 사용한다.
- GUI 한 번의 캐시 갱신으로 옵션 메뉴와 추가 이미지 캐시가 모두 최신 상태가 된다.
- 기존 옵션 메뉴 결과와 독립·내장 복사본 적용에 회귀가 없다.
