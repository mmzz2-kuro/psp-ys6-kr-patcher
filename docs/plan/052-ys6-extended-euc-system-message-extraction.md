# 052. Ys VI 확장 EUC-JP 시스템 메시지 추출 및 작업공간 병합

## 상태

- 사전 조사 완료
- 사용자 확인 완료
- 구현·병합·검증 완료

## 배경

기존 `system-messages.json`은 EBOOT에서 널 바이트로 종료되는 EUC-JP 문자열 구간만 추출해 260개 레코드를 만들었다. 추가 조사 결과, 제어 바이트·줄바꿈·고정 길이 구분자 등으로 이어진 문자열이 현재 작업공간에서 누락된 것을 확인했다.

신뢰 가능한 주요 누락 범위:

- 저장·불러오기·메모리스틱 메시지: 74개
  - EBOOT `0x1223E8`~`0x122DC2`
- 검 마법·검 기술·강화 메시지: 81개
  - EBOOT `0x12DCB4`~`0x12E88C`
- 짧은 개별 후보
  - `アドル`: `0x11EC28`
  - `＜毒＞`: `0x121648`

느슨한 EUC-JP 탐색은 실행 코드가 우연히 일본어처럼 해석되는 오탐을 다수 만들기 때문에, 모든 탐색 결과를 자동 등록해서는 안 된다.

## 목표

1. 널 종료 문자열 외의 실제 EUC-JP 데이터 레코드를 안전하게 추출한다.
2. 실행 코드 오탐을 제외할 수 있는 구조·문자열 품질 조건을 추가한다.
3. 기존 260개 레코드와 사용자가 입력한 번역·상태·메모를 그대로 보존한다.
4. 신규로 확정된 항목만 `untranslated` 상태로 병합한다.
5. GUI 및 기존 시스템 메시지 패치 빌드에서 신규 항목을 동일하게 편집·적용할 수 있게 한다.

## 구현 계획

### 1. 확장 추출 방식

`/tools/scripts/ys6_system_message_workspace.py`의 추출 기능을 확장한다.

- 기존 널 종료 EUC-JP 추출은 유지한다.
- EUC-JP 2바이트 문자, 허용 ASCII, 전각 문자로 구성된 연속 구간을 추가 탐색한다.
- 널 외의 경계 바이트와 다음 문자열까지의 간격을 기록한다.
- 문자열 앞뒤 바이트 문맥을 분석하여 고정 데이터 테이블인지 확인한다.
- 일본어 문장·메뉴명으로 판단 가능한 문자 비율과 최소 길이 조건을 적용한다.
- 실행 코드 영역에서 우연히 나온 짧은 한자 조합은 자동 등록하지 않는다.

### 2. 확정 범위 분리

자동 추출 결과를 다음으로 구분한다.

- `confirmed`: 연속된 문자열 테이블에 포함되고 사람이 읽을 수 있는 실제 일본어
- `candidate`: 실제 문자열 가능성이 있지만 구조 확인이 더 필요한 항목
- `rejected`: 실행 코드 오탐 또는 의미 없는 바이트열

기본 GUI 작업공간에는 `confirmed`만 병합한다. `candidate`는 별도 조사 보고서에 기록하여 필요하면 이후 추가한다.

### 3. 기존 작업공간 보존 병합

병합 키는 원본 EBOOT 오프셋과 원본 바이트 SHA-256을 사용한다.

- 기존 레코드는 번역, 상태, 분류, 메모를 포함해 변경하지 않는다.
- 같은 오프셋에서 원본 바이트가 달라지면 자동 덮어쓰기하지 않고 오류로 중단한다.
- 신규 레코드는 `translation: ""`, `status: "untranslated"`로 추가한다.
- 레코드는 EBOOT 오프셋 순으로 정렬한다.
- 병합 전 JSON 백업을 생성한다.
- `record_count`를 실제 레코드 수에 맞춰 갱신한다.

### 4. 저장·불러오기 문자열 구조 처리

`0x1223E8`~`0x122DC2` 구간에는 화면 한 메시지가 여러 연속 문자열로 나뉜 경우와 `%lu` 같은 서식 지정자가 포함되어 있다.

- 각 저장 단위와 할당 공간을 개별 레코드로 유지한다.
- `%lu`, `KB`, `UMD`, 버튼 표기 같은 ASCII 토큰은 원문 메타데이터에 기록한다.
- 번역에서 필요한 서식 지정자가 사라지거나 변경되면 검증 오류로 차단한다.
- `○`, `×`와 정렬 공백이 포함된 선택 안내는 별도 분류한다.

### 5. 검·마법·강화 문자열 구조 처리

`0x12DCB4`~`0x12E88C` 구간의 검 이름·마법·강화 안내를 추출한다.

- 중복 원문이라도 실제 오프셋이 다르면 별도 레코드로 유지한다.
- 기존 아이템 작업공간과 원문이 겹쳐도 EBOOT의 별도 출력 경로이므로 시스템 메시지 레코드로 관리한다.
- 줄바꿈 또는 제어 바이트로 나뉜 두 문장은 각각의 실제 저장 단위로 유지한다.

### 6. 보고서

`.work/ys6-extended-system-messages/`에 다음 읽기 쉬운 결과를 생성한다.

- 확정 신규 항목 JSON/CSV
- 보류 후보 JSON/CSV
- 오탐 제외 요약
- 병합 전후 레코드 수와 상태별 개수
- 기존 레코드 보존 검증 결과

## 검증 계획

1. 기존 260개 레코드의 오프셋·원본·번역·상태·분류·메모가 병합 전후 동일한지 확인한다.
2. `0x1223E8`의 `データをロードしています。`가 신규 등록되는지 확인한다.
3. `0x12DCB4`의 `剣魔法メイルストロムLv.1`이 신규 등록되는지 확인한다.
4. 실행 코드에서 발생한 의미 없는 EUC-JP 오탐이 기본 작업공간에 등록되지 않는지 확인한다.
5. `%lu` 등 서식 지정자 보존 역테스트가 실패하는지 확인한다.
6. 신규 항목 하나를 임시 번역하여 EUC-JP 전용 인코더와 고정 길이 패치가 동작하는지 확인한다.
7. Python 구문 검사와 전체 ISO preflight를 수행한다.
8. 실제 ISO는 생성하지 않는다.

## 제외 범위

- 신규 시스템 메시지의 한글 번역 작성
- `candidate` 항목의 무조건적인 작업공간 등록
- EBOOT 이외 ISO 파일·압축 아카이브 전체의 범용 EUC-JP 추출
- 문자열 재배치 및 포인터 수정
- ISO 생성

## ROM 처리

- 원본 ISO와 원본 EBOOT는 읽기 전용으로 사용한다.
- 기존 패치 ISO를 수정하거나 새 ISO를 만들지 않는다.
- 분석 및 병합 결과는 `/tools/config`와 `.work`에만 기록한다.
