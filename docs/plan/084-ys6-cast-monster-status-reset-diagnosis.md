# 084. Ys VI GUI 인물·몬스터명 상태 초기화 문제 진단 계획

상태: 완료

## 증상

- GUI의 인물명 또는 몬스터명 영역에서 특정 항목을 `override`로 변경한다.
- 변경한 항목과 다른 항목이 의도하지 않게 `untranslated`로 바뀐다.
- 시스템 메시지에서 수정했던 공유 payload 상태 충돌과 유사해 보이지만 인물·몬스터명 전용 저장 로직을 별도로 확인해야 한다.

## 목적

- 어떤 조작과 데이터 조건에서 다른 항목의 상태가 변경되는지 재현한다.
- GUI 메모리 상태, 저장 직전 데이터, 저장된 JSON의 차이를 비교해 변경 지점을 확정한다.
- 공유 원문, 공유 식별자, 중복 인덱스 또는 필터링된 행의 잘못된 참조 중 어느 것이 원인인지 판단한다.
- 수정이 필요한 정확한 함수와 영향 범위를 제시한다.

## 조사 대상

- 인물명 편집기 행 선택 및 저장 처리
- 몬스터명 편집기 행 선택 및 저장 처리
- `override`, `draft`, `untranslated`, `reviewed` 상태 변환 함수
- 동일 원문 또는 동일 payload를 가진 여러 항목의 동기화 규칙
- 필터링·정렬 후 화면 행 인덱스와 원본 데이터 인덱스 매핑
- 저장할 때 빈 번역을 정규화하는 공통 함수
- 작업공간 로드·검증 과정에서 상태를 다시 계산하는 코드

## 재현 절차

1. 현재 인물·몬스터 작업공간을 읽기 전용 기준본으로 해시 및 상태별 개수를 기록한다.
2. 동일 원문, 동일 payload 해시, 동일 runtime key 또는 인덱스를 공유하는 후보를 찾는다.
3. GUI 저장 함수와 같은 코드 경로를 임시 복사 작업공간에서 호출한다.
4. 후보 한 항목만 `override`로 변경한다.
5. 변경 전후 JSON을 항목 ID 기준으로 비교한다.
6. 요청한 항목 이외에 `untranslated`로 바뀐 항목의 공통 속성을 확인한다.
7. 인물명과 몬스터명을 각각 재현해 동일 원인인지 분리한다.
8. 필터 활성화·비활성화 상태에서도 같은 문제가 생기는지 확인한다.

## 확인할 가능성

- 동일 원문을 공유하는 항목을 일괄 갱신하면서 번역이 없는 형제 항목 상태까지 다시 계산함
- 화면상의 선택 인덱스를 필터 적용 전 원본 목록 인덱스로 잘못 사용함
- 저장 시 한 항목만 보존하고 나머지 상태 필드를 기본값 `untranslated`로 재생성함
- 인물과 몬스터가 같은 payload 식별자를 공유해 서로 덮어씀
- 상태가 행별 속성이 아니라 원문 문자열을 키로 한 임시 딕셔너리에 저장돼 중복 원문이 충돌함

## 산출물

- 최소 재현 사례와 영향받는 항목 ID
- 변경 전후 상태 차이 목록
- 원인 함수와 데이터 흐름
- 인물명·몬스터명 각각의 영향 범위
- 안전한 수정 방향과 필요한 회귀 테스트 목록
- `docs/result/084-ys6-cast-monster-status-reset-diagnosis.md`

## 보존 사항

- 실제 인물·몬스터 작업공간은 수정하지 않는다.
- 재현은 임시 복사본에서 수행한다.
- GUI 코드와 저장 로직은 이번 진단 단계에서 수정하지 않는다.
- 원본 ISO와 패치 ISO는 사용하거나 변경하지 않는다.

## 완료 기준

- 의도하지 않은 `untranslated` 변경을 재현하거나, 재현되지 않을 경우 발생 조건을 데이터상 특정한다.
- 다른 항목이 변경되는 정확한 원인을 코드와 전후 데이터로 입증한다.
- 실제 수정 범위와 회귀 방지 검증안을 사용자에게 제시한다.
