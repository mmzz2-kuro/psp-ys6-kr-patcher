# 114. Ys VI 중복 글리프 코드 호환성 조사 및 수정 계획

상태: 완료

## 배경

- 112·113번 검증 중 revision 4 매핑에서 `쩔`과 `코`가 동일 게임 코드 `0x817E`를 사용하는 중복 1건을 확인했다.
- 두 행은 서로 다른 폰트 인덱스 86과 60을 가리키지만 게임 문자열에는 같은 2바이트 코드가 기록되므로 런타임에서 두 글자를 구분할 수 없다.
- 이 중복은 109번 안전 슬롯 매핑에서 시작되어 revision 4·5에 append-only로 상속됐다.
- 기존 세이브 데이터에 게임 코드가 저장되는 위치가 있다면 단순 재배정은 기존 세이브의 표시를 바꿀 수 있다.

## 목적

- `0x817E`가 런타임 폰트 검색에서 어느 레코드로 해석되는지 확정한다.
- 일반판과 SPECIAL VERSION의 번역·이미지 외 문자열·세이브 관련 데이터에서 `쩔`과 `코` 사용 위치를 전수 조사한다.
- 기존 매핑과 세이브 호환성을 최대한 보존하면서 중복을 제거할 수 있는 안전한 수정안을 결정한다.
- 수정이 필요한 경우 일반판 및 SPECIAL VERSION 배포 매핑과 GUI 빌드를 함께 갱신하고 회귀 검증한다.

## 1. 중복 기원과 런타임 동작 확인

- revision 3·4·5 및 일반판 배포 매핑에서 `0x817E`, `쩔`, `코` 행의 생성 이력을 비교한다.
- 원본 폰트 테이블의 코드 `0x817E` 중복 레코드, 폰트 인덱스 및 비트맵을 추출한다.
- 일반판과 SPECIAL VERSION의 폰트 검색 루틴이 중복 코드에서 첫 번째·마지막·이진 검색 중 어느 레코드를 반환하는지 정적으로 분석한다.
- 필요하면 두 글자를 구분 가능한 시험 문구로 만든 최소 ISO를 별도 생성한다.

## 2. 실제 사용 위치 전수 조사

- 다음 데이터에서 `쩔`과 `코`의 원문 번역 및 최종 인코딩 위치를 검색한다.
  - 일반판 대사, 시스템 메시지, 인물·몬스터명 및 아이템
  - SPECIAL VERSION 최종 IDM 6,156개
  - 이미지·영상 자막을 제외한 실행 파일 문자열
  - 저장·불러오기 위치명과 세이브에 복사될 가능성이 있는 문자열
- 각 글자의 발생 횟수, 리소스 경로, 인덱스와 게임 진행상 노출 가능성을 보고한다.
- 두 글자 중 실제로 사용되지 않는 글자가 있으면 그 사실을 수정안 판단에 반영한다.

## 3. 세이브 호환성 조사

- 저장 파일이 위치명 또는 표시 문자열을 게임 코드 바이트로 직접 보관하는지 기존 세이브 표본과 저장 처리 코드를 확인한다.
- `0x817E`가 세이브에 존재하는지 검색하고, 존재하면 해당 필드와 표시 문맥을 식별한다.
- 기존 세이브에서 기대되는 글자가 `쩔`인지 `코`인지 확정한다.
- 세이브에서 두 의미가 모두 사용될 가능성이 있으면 자동 수정이 불가능한 호환성 한계로 기록한다.

## 4. 수정안 결정

- 조사 결과에 따라 다음 우선순위로 수정안을 선택한다.
  1. 한 글자가 미사용이면 실제 사용 글자의 기존 `0x817E` 표시를 보존하고 미사용 행만 정리한다.
  2. 둘 다 사용되지만 세이브에는 한 글자만 저장된다면 세이브 글자를 `0x817E`에 유지하고 다른 글자를 신규 사용자 정의 코드와 확장 폰트 인덱스에 배정한다.
  3. 둘 다 세이브에 저장될 수 있다면 기존 세이브 자동 호환이 불가능하므로 변환 도구 또는 호환 모드를 별도 계획한다.
- 기존 코드 재배정이 필요한 경우 변경 대상 문자, 리소스 재인코딩 범위와 세이브 영향을 사용자에게 보고하고 다시 확인받는다.

## 5. 매핑 및 빌드 수정

- 승인된 수정안만 일반판 및 SPECIAL VERSION 배포 매핑에 적용한다.
- 영향받지 않는 기존 매핑 행의 순서·코드·폰트 인덱스는 유지한다.
- 새 코드가 필요하면 현재 사용자 정의 영역의 다음 빈 코드와 신규 폰트 인덱스를 사용한다.
- 일반판 GUI 글리프 갱신과 SPECIAL VERSION 고정 revision 매핑이 동일한 중복 검사를 수행하도록 한다.
- 매핑 문서에 호환성 수정 revision과 이전 중복의 처리 근거를 기록한다.

## 6. 검증

- 문자·게임 코드·폰트 인덱스 중복을 일반판 및 SPECIAL VERSION에서 전수 검사한다.
- `쩔`과 `코`가 포함된 모든 번역 바이트를 재추출해 기대 코드와 비교한다.
- 두 글리프의 16×14 비트맵과 실제 출력 미리보기를 생성한다.
- 일반판 전체 사전 검증과 SPECIAL VERSION 6,156개 IDM 검증을 다시 실행한다.
- 기존 세이브 표본에서 위치명과 저장·불러오기 목록이 깨지지 않는지 확인한다.

## 7. GUI 처리

- `inspect` 및 사전 검증에서 매핑 중복이 있으면 문자, 코드와 출처 revision을 표시한다.
- 해결 후에는 신규 중복을 빌드 전에 차단한다.
- 기존 중복을 의도적으로 호환 모드로 유지해야 한다면 경고와 적용 프로필을 명시한다.

## 산출물

- 중복 코드 기원·사용 위치·세이브 영향 보고서
- 필요시 수정된 일반판 및 SPECIAL VERSION 매핑
- 글리프 비교 이미지 및 최소 시험 ISO
- GUI/빌더 중복 검증 보강
- 작업 자료: `tools/patchdata/work/current/114-ys6-duplicate-glyph-code-compatibility`
- 결과 문서: `docs/result/114-ys6-duplicate-glyph-code-compatibility.md`

## 제외 범위

- `0x817E`와 관계없는 글꼴 모양 교정
- 전체 글리프 순서 재배치
- 근거 없이 기존 세이브 문자열을 일괄 변환
- 다른 게임 또는 다른 지역판의 폰트 매핑 변경

## 위험 및 중단 조건

- 기존 세이브가 기대하는 글자를 확정하지 못하면 매핑을 변경하지 않는다.
- 두 글자가 모두 같은 코드로 저장된 기존 세이브가 확인되면 사용자 승인 없이 한쪽 의미를 선택하지 않는다.
- 영향받지 않는 기존 글자의 코드나 폰트 인덱스가 변경되면 시험 ISO를 생성하지 않는다.
- 일반판 또는 SPECIAL VERSION 회귀 검증이 실패하면 배포 매핑과 GUI에 반영하지 않는다.

## 완료 기준

- `0x817E`의 런타임 선택 동작과 실제 사용 위치가 확정된다.
- 세이브 호환 영향과 가능한 수정 범위가 문서화된다.
- 안전한 수정안이 있으면 중복 제거와 두 글자 출력 검증을 완료한다.
- 안전한 자동 수정이 불가능하면 현재 매핑을 유지할 근거와 후속 선택지를 명확히 기록한다.

## 조사 결과 (2026-08-27)

### 중복 기원과 런타임 동작

- 중복은 109번의 원본 미사용 슬롯 배정에서 생겼다. 원본 SPECIAL VERSION 폰트 테이블에 같은 코드 `0x817E`를 가진 레코드가 둘 있었으나, 배정기가 폰트 인덱스만 중복 검사하고 원본 코드 중복을 걸러내지 못했다.
- revision 5 기준 배정은 다음과 같다.
  - `코`: `0x817E`, 가시 폰트 인덱스 60
  - `쩔`: `0x817E`, 가시 폰트 인덱스 86
- 폰트 검색 함수 `0x2D518`~`0x2D550`은 인덱스 0부터 30바이트씩 순회하며 코드가 일치하면 즉시 반환한다. 따라서 앞쪽 인덱스 60의 `코`만 선택되고 인덱스 86의 `쩔`은 도달할 수 없다.
- 현재 결과에서 `코`는 정상이고 `쩔`은 `코`로 잘못 표시된다.

### 실제 사용 범위

- SPECIAL VERSION 최종 번역에서 `쩔`은 16개 문장에 16회 사용된다.
  - base translation: 13회
  - remaining translation: 3회
- `코`는 base translation의 8개 문장에 8회 사용된다. `내 코`, `결코`, `무심코` 등의 실제 표시 문자열이다.
- 두 글자의 확인된 사용 대상은 모두 `s_scene.idm` 대사·행동 설명 리소스다. 저장 지점명을 전달하는 `save.xso.z`, 시스템 메시지, 인물·몬스터명에는 해당 글자가 없다.
- 일반판 고정 매핑은 `쩔=0x9575`, `코=0x9441`로 서로 달라 이 결함의 대상이 아니다.

### 세이브 호환성 판단

- 저장·불러오기 위치명은 각 맵의 `save.xso.z` 문자열을 통해 전달되며, 이번 두 글자는 그 리소스에 사용되지 않는다.
- 작업공간에는 실제 PSP 세이브 표본이 없어 임의 바이트 검색은 수행할 수 없었으나, 두 글자가 들어가는 리소스가 모두 일회성 IDM 표시 문자열이므로 해당 게임 코드가 세이브에 영속화되는 경로는 확인되지 않았다.
- 따라서 `코`의 기존 `0x817E`를 유지하고 `쩔`만 재인코딩하면 기존 세이브의 위치명·목록 호환성에는 영향이 없는 것으로 판단한다.

### 권장 수정안

- 정상 동작 중인 `코=0x817E`, 폰트 인덱스 60은 유지한다.
- 도달 불가능한 기존 `쩔` 행을 최종 매핑에서 제거하고 `쩔`을 다음 빈 사용자 정의 코드 `0xF2DB`, 신규 확장 폰트 인덱스 2304에 다시 배정한다.
- 최종 문자 수는 964자로 유지하고 폰트 테이블만 2,304개에서 2,305개로 늘린다.
- `쩔`이 포함된 SPECIAL VERSION IDM 16개 위치를 새 코드로 재인코딩한다.
- 배포 매핑 revision을 6으로 올리고 빌더가 상속 중복을 허용하던 예외를 제거하여 이후 모든 코드 중복을 사전 검증에서 차단한다.
- 일반판 매핑은 이미 정상이라 변경하지 않고 회귀 검증만 수행한다.
