# 057. Ys VI place_names_02 지역명 행 높이 수정 계획

## 상태

- 완료

## 문제

- `place_names_00`, `place_names_01`의 지역명 조각은 각각 256×32픽셀이다.
- `place_names_02`는 항목 수로 전체 높이를 균등 분할하여 앞의 다섯 조각이
  256×40픽셀, 마지막 조각이 256×56픽셀로 잘못 생성됐다.
- 원인은 추가 이미지 준비 스크립트가 지역명 텍스처의 고정 행 높이를 알지 못하고
  문구 개수에 따라 자동 분할한 것이다.
- 일부 `source_images`에는 PSP 압축 블록 저장 순서 때문에 논리 이미지의 마지막
  4×4 블록이 좌측 상단에 나타나고 나머지 이미지가 밀린 상태가 포함되어 있다.

## 수정 범위

1. `place_names_00`, `place_names_01`, `place_names_02`에 32픽셀 고정 행 분할 규칙을
   적용한다.
2. `place_names_02` 매니페스트 좌표를 다음과 같이 수정한다.
   - line 01: y=0–32
   - line 02: y=32–64
   - line 03: y=64–96
   - line 04: y=96–128
   - line 05: y=128–160
   - line 06: y=160–192
3. 남은 y=192–256 영역은 문구 조각으로 만들지 않고 원본 텍스처에 그대로 둔다.
4. `source_parts/place_names_02`의 6개 PNG를 256×32로 다시 추출한다.
5. 향후 `prepare`를 다시 실행해도 40픽셀로 되돌아가지 않도록 스크립트를 수정한다.
6. `source_images` 전체의 4×4 블록 배치를 진단하고, 오프셋이 확인된 리소스는
   논리 좌표로 회전 복원한다.
7. 매니페스트에 리소스별 블록 오프셋을 기록하여 추출과 재삽입에 같은 역변환을
   적용한다. 정상 리소스는 변환하지 않는다.
8. 교정된 `source_images`와 `source_parts`를 다시 생성한다.

## 검증

- 세 지역명 리소스의 모든 편집 조각이 256×32인지 검사한다.
- `place_names_02` 무수정 재조립에서 원본 RGBA가 유지되는지 확인한다.
- 32픽셀 편집 조각 한 개를 적용한 DXT3 변경 블록 및 할당 공간 검사를 수행한다.
- GUI 패치 데이터 검사에서 오류가 없는지 확인한다.
- 오프셋 교정 이미지를 수정 없이 재삽입했을 때 원본 압축 블록 위치가 유지되는지
  확인한다.
