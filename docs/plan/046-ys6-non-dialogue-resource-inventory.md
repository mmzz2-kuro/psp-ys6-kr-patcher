# 046. 대사 외 시스템·아이템·이미지 자원 전수 조사 계획

## 목적

대사와 인물명 다음 단계로 PSP판 이스 6의 한글화 대상 자원을 전수 조사하고, 번역 및 패치 구현 순서를 결정할 수 있는 목록을 만든다.

이번 조사 대상은 다음과 같다.

1. 시스템 메시지와 공통 안내문
2. 메뉴, 설정, 저장·불러오기 및 전투 UI 문자열
3. 아이템·장비·마법·기술·몬스터 등의 명칭과 설명
4. 이미지에 직접 그려진 일본어
5. 영상 또는 기타 자막 후보

## 현재까지 확인된 기반

- 일반 대사는 XSO 문자열이며 별도 작업공간과 빌더가 완성되어 있다.
- 게임은 EBOOT에 내장된 16×12 1bpp 글리프 테이블을 사용한다.
- `.dds.z` 파일의 해제 후 매직은 일반 DDS가 아니라 `MIG.00.1PSP`로 확인된 바 있다.
- 기존 초기 분석에서는 XSO 외 메뉴·아이템·이미지·EBOOT 문자열을 후속 조사 대상으로 남겼다.
- Windows 한글패치판 데이터가 `/windowVersion`에 있으므로 PSP 자원과 대응하면 번역 및 이미지 자산을 재활용할 가능성이 있다.

## 조사 원칙

- 이번 단계는 위치·포맷·수량·중복 및 런타임 사용 가능성을 파악하는 분석 작업이다.
- 원본 ISO와 기존 패치 ISO를 수정하지 않는다.
- 발견 즉시 번역이나 패치를 임의 적용하지 않는다.
- 추출 결과와 조사 스크립트는 재실행 가능하게 만든다.
- 사용자용 편집기가 필요해지면 `/tools`에 GUI로 추가하고, 전수 분석은 `/tools/scripts`에서 수행한다.

## 1. ISO 자원 인벤토리 재구성

### 대상

- ISO의 전체 파일 경로, 크기, 확장자 및 SHA-256
- `/data/arc/*.bin` 내부 엔트리
- `.z` 컨테이너 해제 후 실제 매직
- EBOOT 및 misc 데이터 파일

### 분류

- XSO: 기존 대사 및 시스템성 스크립트 후보
- 텍스트 테이블: 고정 레코드, 오프셋 테이블, NUL 문자열 풀 후보
- 이미지: MIG/GIM 계열 및 기타 텍스처
- 모델·맵·음성·영상 등 비대상 또는 후순위 자원

산출물에는 독립 파일과 아카이브 내부 복사본의 대응 관계를 포함한다.

## 2. 시스템 및 UI 문자열 조사

### 검색 대상

- ISO 전체의 CP932 일본어 문자열
- EBOOT 내부 문자열
- XSO 중 `dialogue` 역할로 분류되지 않았거나 시스템성 명칭을 가진 문자열
- `misc`, `system`, `menu`, `save`, `load`, `option`, `shop`, `status`, `battle` 관련 파일
- 아카이브 내부의 작은 고정 레코드 또는 문자열 풀

### 분류 기준

- 게임 공통 시스템 메시지
- 메뉴와 버튼 안내
- 저장·불러오기 및 확인창
- 전투 UI와 상태 이상
- 상점 및 장비 UI
- 디버그·개발용 문자열
- 파일명·내부 식별자처럼 번역하면 안 되는 문자열

각 후보에 위치, 바이트 오프셋, 인코딩, 원문, 참조 가능성 및 수정 위험도를 기록한다.

## 3. 아이템명 및 설명 조사

### 대상 범주

- 소비 아이템
- 장비와 액세서리
- 검·에메라스 및 강화 요소
- 퀘스트·이벤트 아이템
- 마법·기술·상태 효과
- 몬스터와 보스 명칭
- 인물·지명 외 도감성 데이터

### 포맷 분석

- 명칭과 설명이 같은 레코드에 있는지 확인한다.
- 고정 길이인지 오프셋 기반인지 확인한다.
- ID, 가격, 능력치 등 비문자 필드를 분리한다.
- 원문 바이트를 재인코딩했을 때 완전히 일치하는지 확인한다.
- 테이블 크기 증가 가능 여부와 포인터 재배치 필요성을 판단한다.

Windows 한글판에서 대응 항목을 추출할 수 있으면 PSP ID·일본어 원문 기준으로 매칭하되 자동 적용하지 않고 대응률과 불일치 목록을 만든다.

## 4. 이미지 자원 조사

### 포맷

- `.dds.z`를 해제하여 `MIG.00.1PSP` 구조를 분석한다.
- 폭·높이·픽셀 포맷·팔레트·밉맵·스위즐 여부를 조사한다.
- 동일 이미지의 독립 파일과 아카이브 내부 복사본을 찾는다.
- 무손실 추출→재구축 round-trip 가능성을 시험한다.

### 일본어 포함 이미지 선별

- 이미지 전체를 썸네일 시트로 렌더링한다.
- OCR은 후보 선별 보조로만 사용하고 시각 검토가 가능한 격자 이미지를 만든다.
- 타이틀, 메뉴, 버튼, 도움말, 로딩, 지역명, 로고 및 튜토리얼 이미지를 우선 표시한다.
- 순수 배경·이펙트·모델 텍스처는 별도 분류한다.

Windows 한글판에 같은 이미지가 있으면 크기·레이아웃·알파·팔레트 차이를 비교하여 직접 이식 가능 여부를 판단한다.

## 5. Windows판 자원 대응 조사

- Windows 한글패치에서 대사 외 문자열 및 이미지 자원을 추출한다.
- 일본어 원문, 내부 ID, 파일명, 이미지 해시 또는 시각적 유사도로 PSP 자원과 대응한다.
- 그대로 사용 가능, 변환 후 사용 가능, 번역만 재사용 가능, 대응 없음으로 분류한다.
- Windows 실행 파일이나 패치 코드에 종속된 자원은 직접 복사하지 않는다.

## 6. 우선순위 산정

각 자원군을 다음 기준으로 평가한다.

- 노출 빈도와 게임 진행 필수성
- 번역 분량
- 포맷 이해도
- 수정 및 재구축 난도
- 화면 검증 용이성
- Windows 한글판 재사용 가능성

권장 기본 순서:

1. 아이템·장비명과 설명
2. 공통 시스템 메시지와 메뉴
3. 전투·상점·상태 UI
4. 텍스트가 포함된 이미지
5. 영상·기타 후순위 자원

실제 조사 결과에 따라 순서를 조정한다.

## 구현 예정 스크립트

필요한 최소 범위에서 다음 비GUI 스크립트를 추가하거나 기존 도구를 확장한다.

- `/tools/scripts/ys6_non_dialogue_inventory.py`
  - ISO·아카이브·EBOOT 문자열과 자원 후보 전수 분류
- `/tools/scripts/ys6_mig_texture.py`
  - MIG 이미지 정보 확인, 추출 및 round-trip 시험
- `/tools/scripts/ys6_texture_contact_sheet.py`
  - 시각 검토용 격자 이미지 생성
- Windows판 대응 분석은 기존 Windows 자원 분석 코드가 재사용 가능하면 확장한다.

GUI 편집기는 포맷과 대상 수가 확정된 후 별도 계획에서 만든다.

## 작업 절차

1. 기존 ISO 인벤토리와 추출 산출물의 재사용 가능 여부를 확인한다.
2. 독립 파일 및 아카이브 내부 자원의 통합 인벤토리를 생성한다.
3. CP932 문자열 후보를 전수 추출하고 역할별로 분류한다.
4. 아이템·설명 테이블 후보의 구조를 분석한다.
5. MIG 이미지 샘플의 포맷을 분석하고 렌더링 PoC를 수행한다.
6. 이미지 썸네일 시트를 생성해 일본어 포함 후보를 목록화한다.
7. Windows 한글판의 대응 텍스트와 이미지를 조사한다.
8. PSP와 Windows 자원의 대응률과 재사용 가능성을 기록한다.
9. 대상별 구현 난도와 우선순위를 정리한다.
10. 결과 문서를 작성하고 다음 구현 계획을 제안한다.

## 검증 기준

- 원본 ISO를 수정하지 않는다.
- 조사 결과가 파일 경로와 오프셋 또는 아카이브 엔트리까지 역추적 가능해야 한다.
- 문자열 후보는 인코딩 round-trip 여부가 기록되어야 한다.
- 아이템·설명 후보는 최소 한 테이블의 레코드 경계와 참조 구조를 설명할 수 있어야 한다.
- 이미지 후보는 최소 한 MIG 샘플을 올바른 크기와 색상으로 렌더링하거나, 실패 시 포맷의 미확정 지점을 구체적으로 기록해야 한다.
- 일본어 포함 이미지 후보를 사람이 확인할 수 있는 격자 이미지로 제공한다.
- 다음 구현 작업을 시스템 텍스트, 데이터 테이블, 이미지로 분리할 수 있어야 한다.
