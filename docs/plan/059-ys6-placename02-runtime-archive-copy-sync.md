# 059. Ys VI placename02 런타임 아카이브 사본 동기화 계획

## 상태

- 완료 (2026-08-20)

## 문제

- 사용자 편집 이미지 `place_names_02/line_05.png`, `line_06.png`는 빌드 입력으로
  정상 인식된다.
- 생성 ISO의 독립 파일
  `PSP_GAME/USRDIR/data/image/placename02.dds.z`에도 두 이미지가 반영된다.
- 그러나 게임에서는 원본 일본어 지역명이 표시된다.
- 원본 ISO를 다시 조사한 결과, 동일한 `placename02.dds.z`가 독립 파일 외에
  14개 맵 아카이브 안에도 들어 있다.
- 기존 빌더는 독립 파일만 교체하고 맵 아카이브 내부 사본은 교체하지 않으므로,
  런타임이 맵 아카이브 사본을 읽는 지역에서는 일본어 원본이 표시된다.

## 확인된 중복 사본

원본 ISO의 독립 파일과 아래 14개 엔트리는 압축 컨테이너 및 해제 payload가
바이트 단위로 동일하다. 각 엔트리의 할당 공간은 8,192바이트다.

## 목표

- 사용자가 편집한 다음 두 지역명이 들어 있는 수정 `placename02.dds.z`를 독립
  파일과 14개 런타임 사본에 동일하게 적용한다.
  - 5행: `クアテラの樹海` → `아쿠에라 수해`
  - 6행: `レダの集落` → `레다 마을`
- 향후 GUI 빌드에서도 같은 누락이 재발하지 않도록 중복 관계를 패치 데이터에
  기록하고 통합 빌더가 자동으로 동기화하게 한다.

## 수정 범위

1. `tools/patchdata/ys6_additional_images/manifest.json`의 `place_names_02`에
   14개 런타임 사본의 아카이브 경로, 엔트리 index, flags를 기록한다.
2. `tools/scripts/ys6_integrated_build.py`에서 추가 이미지 리소스의 런타임 사본
   목록을 읽어 다음 순서로 안전하게 교체한다.
   - 원본 아카이브에서 index·이름·flags가 모두 일치하는 엔트리 선택
   - 원본 엔트리의 압축 컨테이너 또는 해제 payload가 독립 원본과 같은지 확인
   - 독립 파일에 사용한 것과 동일한 수정 컨테이너로 엔트리 교체
   - 기존 아카이브 교체 작업이 있으면 동일 작업본에 누적 적용
3. 통합 빌드 보고서에 리소스별 런타임 사본 수, 교체 성공 수, 대상 아카이브와
   엔트리 정보를 기록한다.
4. 누락, 중복, 원본 불일치, 할당 공간 초과가 하나라도 있으면 빌드를 중단한다.
5. 독립 파일과 14개 사본에는 한 번 생성한 동일 컨테이너를 재사용한다.
6. 058에서 만든 테스트 ISO는 덮어쓰지 않고 059 전용 작업본 ISO를 별도로 만든다.
7. 058 결과 문서의 원인 판단이 잘못됐음을 명시하고, 실제 원인과 059 연결 정보를
   정정한다.

## 검증

1. 원본 ISO 검사
   - 독립 파일 1개와 맵 아카이브 사본 14개가 모두 존재하는지 확인
   - 15개 원본 컨테이너 및 해제 payload가 같은지 확인
   - 각 아카이브 엔트리의 index·이름·flags·할당 크기 확인
2. 단위 및 회귀 검사
   - 런타임 사본 목록 파싱과 정확한 엔트리 선택 검사
   - 원본 불일치, 잘못된 index/flags, 할당 초과 차단 검사
   - 같은 맵 아카이브에 다른 패치가 누적되는 경우 보존 검사
   - 런타임 사본이 없는 기존 추가 이미지 리소스의 동작 유지 검사
3. 통합 사전검사
   - 편집 이미지 2개 인식
   - 독립 `placename02.dds.z` 1개 교체 예정
   - 런타임 사본 14개 교체 예정
   - 모든 컨테이너와 아카이브가 할당 공간 이내
4. 생성 ISO 검사
   - 독립 파일과 14개 런타임 사본을 다시 추출
   - 15개 수정 컨테이너가 바이트 단위로 동일한지 확인
   - 15개 해제 payload가 바이트 단위로 동일한지 확인
   - 각 사본에서 5행과 6행을 PNG로 렌더하여 한글 이미지 반영 확인
   - 나머지 네 지역명과 텍스처의 미편집 블록 유지 확인
5. 원본 보존 검사
   - 원본 ISO SHA-256이 작업 전후 동일한지 확인
   - 생성 ISO가 `/patched/059-placename02-runtime-copy-sync` 아래에만 생성됐는지
     확인

## 제외 범위

- 사용자가 만든 한글 지역명 이미지의 디자인 변경
- `place_names_00`, `place_names_01`의 근거 없는 런타임 사본 자동 추가
- `init.bin/static_tex.dds.z`에 `placename02`를 임의로 추가하는 작업
- 원본 ISO 직접 수정
- 맵 아카이브의 대상 엔트리 외 데이터 재압축 또는 재배치

## 위험 및 대응

- 맵 아카이브는 대사·기타 리소스 패치도 누적 적용될 수 있다. 항상 현재 아카이브
  작업본에 엔트리 교체를 누적하고, 원본 아카이브로 덮어쓰지 않는다.
- 같은 이름의 잘못된 엔트리를 교체하지 않도록 경로·index·이름·flags와 원본
  payload 해시를 함께 검증한다.
- 향후 원본 계열이 달라지면 하드코딩된 목록을 그대로 적용하지 않고 원본 해시
  불일치로 중단한다.

## 복구 방법

- 변경은 매니페스트, 통합 빌더 코드, 별도 059 테스트 ISO에만 적용한다.
- 문제가 발생하면 런타임 사본 동기화 로직과 매니페스트 목록을 되돌리고 원본
  아카이브를 사용한다.
- 원본 ISO와 원본 이미지 작업 공간은 수정하지 않는다.
