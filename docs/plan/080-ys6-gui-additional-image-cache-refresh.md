# 080. Ys VI GUI 추가 이미지 캐시 원버튼 갱신 계획

상태: 완료

## 목적

- 추가 이미지 PNG 또는 매니페스트 변경 후 GUI에서 버튼 한 번으로 사전 컴파일 캐시를 갱신한다.
- 사용자가 별도 명령 프롬프트나 스크립트를 실행하지 않아도 되게 한다.
- 캐시 갱신 성공 후 현재 입력으로 사전검증을 바로 다시 실행할 수 있게 한다.

## UI 변경

1. 기존 `추가 이미지 적용` 체크박스 주변에 `이미지 캐시 갱신` 버튼을 추가한다.
2. 추가 이미지 적용이 활성화됐을 때 버튼을 사용할 수 있게 한다.
3. 버튼을 누르면 GUI에 선택된 원본 ISO와 기본 추가 이미지 작업공간을 사용한다.
4. 처리 중에는 버튼을 비활성화하고 진행 상태 및 현재 리소스 ID를 표시한다.
5. 성공 시 다음 정보를 안내한다.
   - 갱신한 리소스 수
   - 캐시 파일 수와 전체 크기
   - 총 소요 시간
6. 실패 시 실패 리소스와 원인을 표시하고 기존의 정상 캐시는 보존한다.

## 안전한 캐시 갱신

1. 원본 ISO 존재 여부와 SHA-256을 먼저 검증한다.
2. 임시 캐시 디렉터리에 전체 결과를 생성한다.
3. 모든 컨테이너의 압축 해제, payload 해시, 할당 공간을 검증한다.
4. 전체 성공 후에만 기존 `precompiled` 디렉터리를 새 결과로 교체한다.
5. 중단 또는 실패 시 기존 캐시를 그대로 유지하고 임시 결과를 정리한다.

## 캐시 상태 표시

- 캐시 없음
- 최신 캐시
- PNG 변경으로 오래된 캐시
- 매니페스트 변경으로 오래된 캐시
- 원본 이미지 불일치

GUI가 시작되거나 원본 ISO·추가 이미지 옵션이 바뀔 때 빠른 해시 검사로 상태를 갱신한다.

## 실행 흐름

1. 사용자가 수정 PNG를 저장한다.
2. GUI에서 `이미지 캐시 갱신` 버튼을 누른다.
3. GUI가 별도 작업 스레드에서 27개 추가 이미지 리소스를 사전 컴파일한다.
4. 성공하면 캐시 상태를 `최신`으로 변경한다.
5. 이어서 `검증` 또는 `패치 생성`을 실행하면 재인코딩 없이 캐시를 사용한다.

가능하면 성공 후 사전검증을 자동 실행하는 선택 또는 기존 검증 흐름 재호출을 적용한다. 자동 실행이 GUI 사용 흐름을 방해하면 성공 메시지에서 검증 버튼 실행을 안내한다.

## 구현 범위

- GUI 버튼과 상태 표시
- GUI 빌드 작업과 충돌하지 않는 백그라운드 캐시 갱신
- `ys6_additional_image_precompile.py`의 원자적 갱신 및 진행 콜백 지원
- 캐시 상태만 빠르게 검사하는 함수 또는 명령
- 사용자용 오류 메시지의 한글화

## 검증

1. 최신 캐시 상태 판정
2. PNG 한 개 변경 후 오래된 캐시 판정
3. 버튼 한 번으로 캐시 갱신 및 최신 상태 복귀
4. 갱신 중 GUI 응답 유지와 중복 실행 방지
5. 잘못된 ISO 선택 시 갱신 시작 전 차단
6. 의도적인 갱신 실패 시 기존 캐시 보존
7. 갱신 후 GUI 사전검증 성공
8. 갱신 후 ISO 빌드에서 27/27 캐시 사용
9. 기존 079 테스트 ISO와 결과 SHA-256 비교

## 예상 변경 파일

- Ys VI 패치 GUI 파일
- `tools/scripts/ys6_additional_image_precompile.py`
- 필요 시 `tools/scripts/ys6_patch_builder.py`
- 캐시 상태 검사 테스트
- `docs/result/080-ys6-gui-additional-image-cache-refresh.md`

## 보존 사항

- 원본 ISO를 수정하지 않는다.
- 캐시 갱신 중 기존 정상 캐시를 직접 덮어쓰지 않는다.
- 추가 이미지 적용 체크박스의 기존 의미를 변경하지 않는다.
- PNG 변경이 없는 일반 검증·빌드에서는 캐시를 다시 생성하지 않는다.
- 테스트 ISO는 필요할 때만 `/patched/080-ys6-gui-additional-image-cache-refresh/`에 한 개 생성한다.

## 완료 기준

- GUI에서 한 번의 버튼 조작으로 추가 이미지 캐시가 갱신된다.
- 실패 시 기존 캐시가 보존된다.
- 갱신 상태와 결과가 사용자에게 명확히 표시된다.
- 갱신 후 검증·빌드가 캐시를 사용하며 기존 결과와 동일하다.
- 결과 문서에 변경 파일과 검증 결과를 기록한다.
