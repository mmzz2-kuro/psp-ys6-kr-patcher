# 086. Ys VI 오리오 열매 구매 후 아이템 미표시 문제 진단 계획

상태: 사용자 확인으로 종료 — 세이브 데이터 문제

## 증상

- 상점에서 `오리오 열매`를 구매하면 Gold는 정상적으로 차감된다.
- 구매 후 실제 아이템 목록에서는 오리오 열매가 보이지 않는다.
- 같은 상점 또는 같은 계열로 보이는 `카미오 꽃`, `리므리아 버섯`은 정상 구매된다.
- 현재 단계에서는 세이브 데이터 문제인지 한글 패치의 아이템 데이터 문제인지 확정되지 않았다.

## 목적

- 구매 동작에서 사용되는 오리오 열매의 아이템 ID와 아이템 목록 표시 ID가 일치하는지 확인한다.
- 한글 아이템 이름·설명 패치가 레코드 경계, ID, 타입 또는 표시 조건을 손상시켰는지 확인한다.
- 세이브 파일의 보유 수량 슬롯에 구매 결과가 실제로 기록되는지 확인한다.
- 원본 일본어 ISO, 현재 패치 ISO 및 가능하면 문제 세이브를 비교해 세이브 문제와 패치 문제를 분리한다.

## 우선 가설

1. 오리오 열매의 번역 레코드가 잘못된 인덱스 또는 아이템 ID에 적용됨
2. 이름·설명 길이 또는 레코드 패치가 인접 필드를 침범해 아이템 종류·표시 플래그가 변경됨
3. 상점 판매 ID와 인벤토리 ID가 서로 다른 별칭 또는 중복 엔트리를 가리킴
4. 아이템 목록의 필터나 정렬 조건 때문에 수량은 증가했지만 다른 분류에 표시됨
5. 세이브의 해당 아이템 수량 슬롯이 이미 상한 또는 특수값이며 구매 처리와 표시가 어긋남
6. 기존 세이브가 패치 이전 데이터 구조 또는 비정상 수량 값을 가지고 있음
7. 원본 게임 자체의 진행 플래그·소지 제한·일회성 조건

## 정적 조사

1. 아이템 작업공간에서 다음 세 항목을 비교한다.
   - 오리오 열매
   - 카미오 꽃
   - 리므리아 버섯
2. 각 항목의 인덱스, resource ID, 일본어 원문, 번역, 상태, 원본 레코드 SHA-256을 기록한다.
3. 원본 EBOOT 또는 아이템 데이터에서 세 항목의 레코드를 바이트 단위로 비교한다.
4. 현재 패치 빌드 결과에서 실제 적용된 이름·설명 레코드를 다시 추출한다.
5. 이름·설명 이외의 ID, 타입, 가격, 보유 한도, 표시 플래그가 변경됐는지 확인한다.
6. 상점 데이터에서 세 항목의 판매 ID와 가격을 찾아 비교한다.
7. 오리오 열매와 동일 ID 또는 동일 원문을 공유하는 중복 엔트리가 있는지 확인한다.

## 세이브 분리 진단

세이브 파일이 제공되거나 저장소에서 안전하게 식별될 경우 다음을 수행한다.

1. 원본 세이브를 복사하고 해시를 기록한다.
2. 구매 직전과 구매 직후 세이브가 모두 있으면 바이트 차이를 비교한다.
3. 카미오 꽃·리므리아 버섯 구매 전후 변화와 오리오 열매 구매 전후 변화를 비교한다.
4. 오리오 열매로 추정되는 수량 슬롯이 증가하는지 확인한다.
5. 수량이 증가했는데 화면에만 없다면 표시/아이템 테이블 문제로 분류한다.
6. 수량이 증가하지 않았다면 상점 ID·소지 제한·게임 로직 또는 세이브 슬롯 문제로 분류한다.

세이브가 없어도 정적 조사와 패치 ISO 비교는 먼저 진행한다. 세이브가 반드시 필요한 단계에 도달했을 때 필요한 파일과 시점을 구체적으로 요청한다.

## 패치와 세이브 문제 분리 기준

| 확인 결과 | 판단 |
|---|---|
| 원본 ISO에서도 같은 세이브로 재현 | 세이브 또는 원본 게임 조건 가능성 높음 |
| 원본 ISO는 정상, 패치 ISO만 재현 | 패치 문제 가능성 높음 |
| 새 세이브는 정상, 기존 세이브만 재현 | 기존 세이브 문제 가능성 높음 |
| 수량 슬롯은 증가하지만 목록에 미표시 | 아이템 표시 데이터 또는 분류 문제 |
| Gold만 감소하고 수량 슬롯 변화 없음 | 상점 ID·구매 로직·소지 제한 문제 |
| 인접 아이템 레코드까지 변경 | 아이템 패치 범위 또는 레코드 경계 오류 |

## 검증

- 실제 작업공간과 세이브는 수정하지 않고 복사본 또는 읽기 전용으로 조사한다.
- 세 항목의 원본·패치 레코드를 바이트 단위로 대조한다.
- GUI 아이템 번역 저장 결과와 ISO 내부 적용 결과가 일치하는지 확인한다.
- 원인 후보를 정적 증거로 좁히고, 가능하면 최소 재현 조건을 제시한다.
- 수정이 필요하면 정확한 파일과 영향 범위를 별도 계획으로 제안한다.

## 예상 산출물

- 세 아이템의 ID·인덱스·가격·타입 비교표
- 원본과 패치 아이템 레코드 차이
- 상점 판매 ID와 인벤토리 ID 연결 결과
- 세이브 문제 또는 패치 문제에 대한 판단과 근거
- 추가로 필요한 세이브 파일이 있다면 정확한 요청 목록
- `docs/result/086-ys6-orio-fruit-purchase-missing-item-diagnosis.md`

## 보존 사항

- 실제 세이브 파일을 수정하지 않는다.
- 원본 ISO와 기존 패치 ISO를 수정하지 않는다.
- 이번 진단 단계에서는 아이템 번역, 게임 데이터 또는 GUI 코드를 수정하지 않는다.
- 테스트 세이브나 ISO가 필요하면 복사본의 목적과 위치를 결과 문서에 기록한다.

## 완료 기준

- 오리오 열매의 구매 ID와 인벤토리 ID 및 패치 레코드를 확인한다.
- 세이브 문제와 패치 문제 중 어느 쪽 가능성이 높은지 근거를 들어 판단한다.
- 현재 자료만으로 확정할 수 없다면 필요한 구매 전·후 세이브 또는 비교 절차를 명확히 제시한다.
