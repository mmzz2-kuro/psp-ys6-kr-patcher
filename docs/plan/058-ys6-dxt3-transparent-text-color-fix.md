# 058. Ys VI DXT3 투명 이미지 글자 색상 압축 수정 계획

## 상태

- 완료 후 원인 판단 정정 (2026-08-20)
- 게임에서 일본어 원본이 보인 직접 원인은 DXT3 색상 압축이 아니라 14개 맵
  아카이브 런타임 사본의 교체 누락이었으며, 후속 059에서 수정했다.

## 문제

- `place_names_02`의 편집 이미지 2개는 GUI 빌드에서 정상 인식됐다.
- 생성 ISO에도 `PSP_GAME/USRDIR/data/image/placename02.dds.z`가 실제로 교체됐다.
- `place_names_02`는 현재 확인된 구조상 `init.bin/static_tex.dds.z`에 중복 사본이
  없는 독립 이미지 리소스다.
- 그런데 생성 ISO에서 해당 텍스처를 다시 추출하면 한글 글자의 알파값은 남지만
  RGB가 검은색에 가깝게 압축된다. 게임의 어두운 배경에서는 글자가 보이지 않는다.

## 원인

- DXT3는 RGB 색상 블록과 명시적 4비트 알파 블록을 따로 저장한다.
- 현재 구현은 Pillow가 생성한 DXT3 RGB 블록을 그대로 사용하면서 알파 블록만
  편집 PNG 기준으로 다시 기록한다.
- 투명 배경 픽셀이 `(0, 0, 0, 0)`인 이미지에서는 색상 압축기가 투명 픽셀의 검은
  RGB까지 색상 후보에 포함한다.
- 흰색 반투명 글자보다 투명 검은 배경의 비중이 훨씬 크기 때문에 RGB 끝점이 검은색
  위주로 선택되고, 알파가 있는 글자까지 검게 복원된다.

## 수정 범위

1. `/tools/scripts/ys6_additional_image_patch.py`에 DXT3 전용 색상 블록 인코더를
   추가한다.
2. 색상 끝점 계산 시 알파가 0인 픽셀의 RGB는 제외한다.
3. 반투명 픽셀은 표시 기여도가 높도록 알파값을 반영해 색상 후보를 선정한다.
4. 가시 픽셀이 없는 완전 투명 블록은 원본 RGB 블록을 유지하고 알파만 0으로
   기록한다.
5. 가시 픽셀이 있는 블록은 기존 DXT1 고품질 RGB565 탐색을 4색 불투명 모드로
   재사용하되, DXT3 알파 블록은 별도로 정확히 양자화한다.
6. 수정되지 않은 4×4 블록은 원본 바이트를 그대로 유지한다.
7. 057에서 추가한 논리 블록 오프셋과 물리 저장 블록 역변환은 유지한다.

## 검증

1. 현재 사용자가 편집한 다음 파일을 실제 입력으로 사용한다.
   - `edited_parts/place_names_02/line_05.png`
   - `edited_parts/place_names_02/line_06.png`
2. 재압축 후 다음 항목을 검사한다.
   - 흰색 글자의 복원 RGB가 검은색으로 변하지 않는지
   - DXT3 4비트 알파가 편집 PNG와 허용 오차 범위에서 일치하는지
   - 투명 배경이 불투명해지지 않는지
   - 256×32 조각 좌표가 유지되는지
3. 원본과 수정본의 RGB·알파 오차 보고서를 생성한다.
4. `place_names_00`, `place_names_01` 및 다른 DXT3 리소스에 단일 블록
   회귀 검사를 수행한다.
5. GUI 통합 사전검사에서 다음을 확인한다.
   - `place_names_02` 편집 이미지 2개 인식
   - `placename02.dds.z` 교체 목록 포함
   - 컨테이너 할당 공간 초과 없음
6. 생성 ISO에서 `placename02.dds.z`를 다시 추출해 한글 글자가 보이는 PNG를
   확인용으로 남긴다.
7. 원본 ISO SHA-256이 변경되지 않았는지 확인한다.

## 복구 방법

- 변경은 인코더 코드와 별도 패치 ISO에만 적용한다.
- 문제가 발생하면 DXT3 전용 색상 인코더 변경을 되돌리고 기존 원본 컨테이너를
  사용한다.
- 원본 ISO와 `source_images`는 수정하지 않는다.
