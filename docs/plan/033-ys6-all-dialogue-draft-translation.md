# Ys VI 전체 미번역 dialogue draft 번역 계획

## 상태

- 최초 범위: `s_0202` 51개
- 범위 변경 사용자 확인: 완료
- 전체 대상 고정: 완료
- 번역: 진행 예정
- 작업공간 병합: 미착수
- GUI 검토: 미착수
- 결과 문서: `/docs/result/033-ys6-all-dialogue-draft-translation.md`

## 목표

전체 카탈로그에서 아직 번역되지 않은 `dialogue` 역할 문자열을 모두 한국어로 번역해 `draft`로 저장한다. 사용자는 GUI에서 원하는 순서로 검토·교정하고, 패치에 넣을 항목만 `override`로 변경한다.

`draft`는 번역문이 존재해도 패치 ISO에 포함되지 않는다.

## 현재 고정 범위

- 전체 카탈로그: 7,424개
- 기존 override: 142개
- 기존 draft: 19개
- 신규 번역 대상 dialogue: 4,634개
- 대상 XSO 경로: 478개
- 대상 맵: 98개

선택지, 화자명, 리소스명, 스크립트 경로 및 `unreferenced`만 있는 문자열은 이번 범위에서 제외한다. 하나의 문자열에 `dialogue`와 다른 역할이 함께 있으면 dialogue로 포함한다.

## 상태 및 보호 규칙

- 기존 `override`는 번역·상태·메모를 변경하지 않는다.
- 기존 `draft`는 사용자가 교정했을 수 있으므로 자동으로 덮어쓰지 않는다.
- 신규 대상은 현재 `untranslated`인 dialogue만 해당한다.
- 신규 번역은 모두 `draft`로 저장한다.
- Codex가 임의로 `override`로 전환하지 않는다.
- 원문 SHA가 달라지면 병합하지 않고 중단한다.
- 대상 목록은 작업 시작 시 snapshot으로 고정하며, 진행 중 사용자 변경은 병합 전에 다시 비교한다.

## 번역 단위

최종 작업공간에는 한꺼번에 표시하지만 번역 산출물은 맵 그룹/XSO 단위 배치로 나눈다.

권장 순서:

1. `s_02` — 960개
2. `s_05` 및 `s_0502` — 333개
3. `s_00` — 371개
4. `s_06`, `s_10`, `s_15`, `s_20`, `s_25`, `s_30`
5. `s_35`, `s_36`
6. `s_40` — 1,091개
7. `s_45`, `s_46` 및 세부 그룹
8. `s_50`, `s_55`, `s_65`, `s_66`, `s_70`
9. `s_90`, `s_hidden0`, `s_hidden1`

하나의 XSO를 중간에서 자르지 않고, 같은 이벤트의 문자열을 함께 번역한다.

## 번역 기준

- XSO 안의 전체 원문 순서와 주변 문자열을 함께 확인한다.
- 인물별 말투를 가능한 한 일관되게 유지한다.
- 확정 인물명은 `/tools/config/cast-names.json`의 번역을 우선한다.
- 지명·종족·조직·아이템 용어집을 누적 관리한다.
- `\\x1`, `\\n` 등 제어 토큰을 정확히 보존한다.
- color·scale 등 게임 마크업을 보존한다.
- 일본어 발음용 ruby를 제거하면 `allow_markup_change`와 메모를 기록한다.
- 화면 폭을 고려해 지나치게 긴 문장을 피한다.
- 해석이나 화자가 불명확하면 메모에 `검토 필요`를 표시한다.
- 중복 원문은 문맥이 같을 때만 번역을 재사용한다.

## 작업 데이터

- 대상 snapshot: `/.work/ys6-all-dialogue-draft/target-snapshot.json`
- 진행 manifest: `/.work/ys6-all-dialogue-draft/progress.json`
- 배치 번역: `/.work/ys6-all-dialogue-draft/batches/<map-group>/*.json`
- 용어집: `/tools/config/dialogue-glossary.json`
- 최종 작업공간: `/tools/config/dialogue-translations.json`

각 배치에는 `(iso_path, string_index)`, 원문, 원문 SHA, 번역, 토큰, 마크업 변경 허용 및 메모를 기록한다.

## 병합 방식

1. 대상 snapshot과 현재 작업공간 비교
2. 현재 상태가 여전히 `untranslated`인 항목만 병합
3. 사용자가 먼저 번역·상태 변경한 항목은 자동 건너뛰고 보고
4. 제어 토큰과 마크업 검증
5. 전체 작업공간 검증
6. 원자적 JSON 저장 및 백업
7. 진행 manifest 갱신

부분 배치가 완성될 때마다 안전하게 병합할 수 있으나, 모든 항목은 상태상 동일한 `draft`이며 GUI에서는 하나의 목록으로 보인다.

## GUI 사용

- 상태 필터 `draft`로 모든 초벌 번역 확인
- 맵, XSO, 일본어 원문 또는 한국어 번역 검색
- 교정 후 상태를 `override`로 변경
- GUI 패치 빌드는 override만 적용하고 남은 draft를 제외

후속 개선이 필요하면 XSO/검색 결과 일괄 override 기능을 별도 계획으로 추가한다.

## 검증

- 신규 draft 4,634개 또는 사용자 선행 변경을 제외한 정확한 잔여 수
- 대상 478개 XSO 누락 없음
- 신규 항목이 모두 dialogue 역할
- 기존 override 142개 내용·상태 유지
- 기존 draft 19개 내용·상태 유지
- 빈 번역 0건
- 원문 SHA 불일치 0건
- 제어 토큰 손실 0건
- 미승인 마크업 변경 0건
- 중복 키 0건
- 작업공간 전체 검증 통과
- draft가 패치 빌드에서 제외됨
- 자동 테스트 및 Python 컴파일 통과

## ISO 처리

전체 draft 생성만으로 ISO를 만들지 않는다. 사용자가 GUI에서 검토 후 override로 전환한 항목은 GUI의 `패치 빌드` 탭을 통해 적용한다.

## 완료 조건

- 전체 미번역 dialogue 대상이 한국어 draft로 채워진다.
- 기존 사용자 번역과 승인 상태가 보존된다.
- GUI에서 전체 draft를 검토하고 선택적으로 override할 수 있다.
- draft가 패치에 포함되지 않는 기존 보장이 유지된다.
- 진행·검증 결과가 문서화된다.

## 중단 및 재확인 조건

- snapshot 이후 대규모 사용자 상태 변경으로 안전한 병합이 어려움
- 원문만으로 화자·문맥을 판별할 수 없는 대규모 구간
- 제어 토큰 또는 마크업 구조가 기존 검증기로 처리되지 않음
- 전체 번역에 필요한 용어 표기를 사용자 결정 없이 확정하기 어려움
- 기존 override/draft를 덮어쓸 위험 발생
