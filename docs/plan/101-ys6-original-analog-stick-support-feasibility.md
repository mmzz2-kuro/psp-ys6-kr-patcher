# 101. Ys VI 기존 원본판 아날로그 스틱 지원 가능성 조사 계획

상태: 완료

## 목적

- 기존 지원판 `ULJM-05009`에서 아날로그 스틱으로 캐릭터를 조작할 수 있게 패치 가능한지 조사한다.
- `ULJM-05155 SPECIAL VERSION`에 아날로그 조작 코드가 추가돼 있다면 입력 처리 차이를 분석해 기존판으로 이식할 수 있는지 판단한다.
- 현재 한글 패치 EBOOT과 충돌하지 않는 최소 변경 방식을 찾는다.

## 대상

- 기존판 `PSP_GAME/SYSDIR/BOOT.BIN` 및 현재 한글 패치용 복호화 EBOOT
- SPECIAL VERSION `PSP_GAME/SYSDIR/BOOT.BIN`
- PSP 컨트롤러 입력 구조체와 버튼·아날로그 값 참조 코드

## 조사 절차

### 1. 기능 존재 여부 확인

- SPECIAL VERSION이 실제 게임 이동에서 아날로그 스틱을 사용하는지 실행 코드 기준으로 확인한다.
- PSP 입력 API 호출 또는 컨트롤러 데이터 구조의 `Lx`, `Ly` 바이트 참조를 검색한다.
- 기존판과 SPECIAL VERSION에서 같은 입력 함수·호출자를 구조적으로 대응시킨다.

### 2. 입력 처리 루틴 비교

- 방향키 비트 입력을 이동 방향으로 변환하는 기존판 루틴을 찾는다.
- SPECIAL VERSION의 아날로그 중심값, 데드존, 축 반전과 8방향 또는 연속 방향 변환 로직을 확인한다.
- 필드 이동, 메뉴, 대화 선택과 미니게임이 같은 입력 루틴을 공유하는지 구분한다.

### 3. 이식 방식 검토

- 기존 입력 버퍼에 아날로그 값을 방향키 비트로 합성하는 최소 방식과, 실제 이동 벡터를 연속값으로 전달하는 방식의 가능성을 비교한다.
- 코드 빈 공간, 분기 거리, 레지스터 사용과 호출 규약을 확인한다.
- 현재 한글 폰트·시스템 메시지 패치 영역과 코드 변경 범위가 겹치는지 확인한다.

### 4. 최소 패치 시안

- 안전한 위치가 확인되면 원본 파일을 수정하지 않고 작업용 복호화 EBOOT에 최소 패치 시안을 만든다.
- 우선 아날로그를 방향키 8방향으로 변환하는 보수적인 시안을 검토한다.
- 데드존은 PSP 중심값을 기준으로 설정하고, 방향키 입력은 기존처럼 함께 사용할 수 있게 한다.
- 구조가 불명확하거나 코드 공간이 부족하면 시안 적용을 중단하고 필요한 후속 분석을 기록한다.

### 5. 검증

- 패치 전후 ELF 구조와 변경 바이트 범위를 확인한다.
- 변경 영역이 승인된 입력 루틴과 코드 주입 공간으로 제한되는지 검사한다.
- 정적 검증 후 PPSSPP 또는 PSP 실기에서 이동, 대각선, 중립 복귀, 방향키 병행 입력을 확인할 수 있는 시험 파일을 준비한다.

## 고려 사항

- 8방향 변환은 구현이 비교적 단순하고 기존 이동 시스템과 호환되지만 아날로그 세기에 따른 속도 변화는 제공하지 않는다.
- 연속 방향 방식은 자연스럽지만 게임 내부 이동 벡터 구조까지 수정해야 할 수 있어 위험이 크다.
- 메뉴까지 아날로그를 적용하면 의도하지 않은 연속 입력이 생길 수 있으므로 기본 조사 범위는 필드 이동이다.
- SPECIAL VERSION이 아날로그를 사용하지 않는다면 PSP SDK 입력 구조와 기존판 코드만으로 별도 구현 가능성을 판단한다.

## 안전 조건

- 두 원본 ISO는 수정하지 않는다.
- 조사 단계에서 전체 GUI 빌더에는 연결하지 않는다.
- 테스트 ISO 생성이 필요하면 정적 패치 범위가 확인된 후 별도 작업본으로만 만든다.
- 세이브 데이터 형식과 게임 데이터는 변경하지 않는다.

## 완료 기준

- 기존판과 SPECIAL VERSION의 아날로그 입력 처리 차이를 설명할 수 있다.
- 기존판에 적용 가능한 패치 방식과 난이도·위험을 판단한다.
- 가능하면 최소 패치 시안의 위치와 검증 방법을 제시한다.
