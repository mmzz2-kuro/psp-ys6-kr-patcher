# 049. 시스템 메뉴 메시지 위치 조사 계획

## 목적

PSP판 이스 6의 저장·불러오기·옵션·확인창 등 시스템 메뉴 문구가 저장된 위치와 포맷을 찾는다.

첫 기준 문자열은 사용자가 제시한 다음 문구다.

- `データをセーブします`

이 문구 또는 조사 과정에서 확인되는 정확한 변형을 기준으로 정적 파일과 런타임 메모리를 연결한다.

## 현재 상태

- 일반 대사는 XSO와 런타임 아카이브 매핑이 완료됐다.
- 인물·몬스터명은 `castinfo.dat`에 있다.
- 아이템 이름·설명은 `invinfo.dat`에 있다.
- 단순 EBOOT CP932 전수 검색은 실행 코드의 우연한 바이트열 때문에 오탐이 많았다.
- 시스템 메뉴의 상당 부분은 이미지일 가능성도 있으므로 텍스트 렌더와 이미지 렌더를 구분해야 한다.

## 조사 원칙

- 이번 단계는 위치·인코딩·참조 방식을 확인하는 분석 작업이다.
- 원본 ISO와 현재 패치 ISO를 수정하지 않는다.
- 문구를 발견해도 사용자 확인 없이 번역·삽입하지 않는다.
- 정적 검색 결과는 원문 재인코딩과 주변 구조 검증을 통과한 것만 확정 후보로 취급한다.
- PPSSPP 런타임 조사가 필요하면 실행·도착·종료 시점을 사용자와 맞춘다.

## 1. 기준 문자열 확정

다음 변형을 함께 검색한다.

- `データをセーブします`
- `データをセーブしますか`
- `セーブします`
- `セーブ`
- 문장 끝 `。`, `？`, 개행 및 제어 코드 포함 변형
- Windows 일본어판 또는 한글판의 대응 저장 문구

CP932 바이트와 UTF-16LE/BE 바이트를 모두 생성해 정확 검색한다.

## 2. 정적 자원 검색

### ISO 독립 파일

- `PSP_GAME/SYSDIR/BOOT.BIN`
- `PSP_GAME/SYSDIR/EBOOT.BIN`
- `PSP_GAME/USRDIR/data/misc/*`
- `PSP_GAME/USRDIR/data/menu/*`
- `.dat`, `.bin`, `.txt`, `.xso.z`

### 압축·아카이브 내부

- `.z` 해제 payload
- `data/arc/*.bin` 내부 엔트리
- 일반 대사 역할이 아닌 XSO
- `init.bin` 및 공통 시스템 아카이브

각 발견 후보에 다음을 기록한다.

- ISO 경로
- 아카이브명과 엔트리 인덱스
- payload 오프셋
- 원문 바이트와 인코딩
- 주변 문자열 또는 레코드 구조
- 독립 파일과 아카이브 복사본 관계

## 3. Windows판 대응 검색

- `/windowVersion`의 일본어·한글 시스템 자원을 검색한다.
- Windows 아카이브의 저장·불러오기 관련 파일과 문자열을 추출한다.
- PSP와 파일명, 주변 문자열, 리소스 ID 또는 문구 순서로 대응한다.
- Windows 한글 문구는 위치 확인과 번역 참고용으로 사용하고 직접 복사하지 않는다.

## 4. 이미지 여부 판별

저장 화면 관련 `menu` 이미지 후보를 확인한다.

- `save*.dds`
- `load*.dds`
- `w_asksave*.dds`
- `w_askload*.dds`
- 메시지 박스 및 버튼 이미지

문구가 텍스트 테이블에 없으면 다음을 구분한다.

- 문장 전체가 이미지에 포함됨
- 제목·버튼만 이미지이고 안내 문장은 런타임 텍스트
- Windows판만 이미지이고 PSP판은 다른 구조

MIG 디코더가 아직 완전하지 않으므로 파일명·Windows 대응·PPSSPP 화면/텍스처 덤프를 보조로 사용한다.

## 5. 런타임 메모리 추적

정적 검색으로 위치를 확정하지 못할 때 수행한다.

1. PPSSPP에서 저장 확인 메시지가 나오기 직전에 일시정지
2. 메시지 표시 전 메모리 덤프
3. 메시지 표시 후 메모리 덤프
4. CP932 기준 문자열과 포인터 후보 검색
5. 전후 차분으로 새로 로드된 버퍼 확인
6. 파일 읽기 로그 또는 메모리 참조를 통해 ISO 자원으로 역추적

세이브 스테이트로 문자열 캐시가 남는 영향을 피하기 위해 필요한 경우 새 실행과 일반 게임 저장을 사용한다.

## 예정 스크립트

필요한 최소 범위에서 다음을 추가하거나 기존 코드를 확장한다.

- `/tools/scripts/ys6_system_string_search.py`
  - 문자열 변형 인코딩 및 ISO·z payload·아카이브 정확 검색
- `/tools/scripts/ys6_runtime_string_diff.py`
  - 런타임 덤프 전후 기준 문자열과 주변 바이트 차분

사용자가 직접 편집하는 GUI는 위치와 포맷이 확정된 후 별도 계획에서 추가한다.

## 검증 기준

- 기준 문구가 발견되면 경로·오프셋·바이트가 재현 가능해야 한다.
- 발견 위치의 원문을 다시 CP932로 인코딩했을 때 원본 바이트와 같아야 한다.
- 아카이브 내부라면 엔트리 인덱스·플래그·할당 크기를 기록한다.
- 정적 파일을 임시 수정하지 않고도 런타임 사용 자원임을 설명할 근거를 확보한다.
- 텍스트가 아닌 이미지라면 대응 이미지와 근거를 기록한다.
- 찾지 못하면 검색한 범위와 다음 런타임 조사 지점을 구체적으로 남긴다.
