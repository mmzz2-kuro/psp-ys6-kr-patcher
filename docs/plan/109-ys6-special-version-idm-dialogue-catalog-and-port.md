# 109. Ys VI SPECIAL VERSION IDM 전체 대사 카탈로그 및 번역 이식 계획

상태: 테스트 ISO 생성 완료 / 사용자 실기 확인 대기

## 배경

- 106번에서 SPECIAL VERSION의 초반 대사가 기존 XSO가 아니라 새 `s_scene.idm` 형식으로 이동한 것을 확인했다.
- `s_0551` IDM의 201개 레코드와 214개 문자열을 완전히 파싱하고, 기존 XSO index 35~45의 번역 11개를 이식해 실기 출력을 확인했다.
- SPECIAL VERSION ISO에는 `PSP_GAME/USRDIR/data/idm` 아래 `s_scene.idm`이 241개 있으며 총 크기는 419,539바이트다.
- 기존 XSO 구조 대응만으로 적용된 번역은 190개이므로, 전체 대사 이식률을 높이려면 IDM 전용 카탈로그와 대응표가 필요하다.

## 목적

- SPECIAL VERSION의 241개 IDM을 전부 파싱해 레코드·문자열 카탈로그를 만든다.
- 독립 IDM과 `data/arc/s_*.bin` 내부 런타임 복사본 관계를 확정한다.
- 기존 ULJM-05009 번역 7,424개와 SPECIAL VERSION IDM 문자열의 안전한 자동 대응 범위를 산출한다.
- 자동 대응이 확실한 IDM 번역을 SPECIAL VERSION 전용 작업공간과 빌더에 반영한다.
- 현재 434개 안전 글리프 슬롯의 용량 한계를 계산하고, 가능한 범위의 2차 테스트 ISO를 만든다.

## 1. IDM 파서 분리 및 형식 검증

- 106번 빌더 내부의 IDM 파서·재구성기를 별도 공용 모듈로 분리한다.
- 241개 IDM 전체에 다음 검사를 수행한다.
  - 16바이트 헤더와 version
  - 레코드 수
  - 문자열 수와 인자 수
  - 가변 인자 배열
  - CP932 문자열 길이와 파일 경계
  - 파일 끝까지 잔여 바이트 없이 파싱
- 모든 IDM을 무수정 재구성하고 원본과 바이트 단위로 비교한다.
- 형식 변형이나 파싱 실패 파일은 별도 목록으로 분리한다.

## 2. IDM 카탈로그와 런타임 맵

- 각 IDM 문자열에 다음 정보를 기록한다.
  - 맵 ID와 ISO 경로
  - 레코드 index 및 record ID
  - 레코드 내부 string index와 전체 flat index
  - 인자 배열
  - 일본어 원문, raw hex와 SHA-256
- 같은 맵의 `data/arc/s_*.bin`을 조사해 동일 `s_scene.idm` 엔트리를 연결한다.
- 독립·아카이브 복사본의 원본 동일성, 엔트리 index, flags, 원본 크기와 할당 공간을 기록한다.
- 같은 IDM이 여러 아카이브에 존재하면 모든 런타임 복사본을 포함한다.

## 3. 기존 번역 대응

- 기존 XSO 번역과 IDM 원문을 다음 우선순위로 대응한다.
  1. 같은 맵에서 raw 원문이 한 위치에 고유하게 일치
  2. 같은 맵에서 동일 원문이 여러 번 나오지만 주변 앞뒤 원문 문맥이 일치
  3. 기존 XSO의 연속 대사 구간과 IDM 레코드의 연속 문자열 구간이 일치
  4. 맵 구조가 이동된 경우 전체 IDM에서 고유 원문과 인접 문맥이 함께 일치
- 원문 하나만 같고 문맥이 다른 항목은 자동 이식하지 않는다.
- 같은 IDM 위치에 서로 다른 번역이 대응되면 충돌로 중단한다.
- 기존 상태가 `override`인 번역만 실제 패치 후보로 사용한다.
- 자동 대응, 문맥 대응, 모호함, 미대응 및 충돌 수를 보고한다.

## 4. SPECIAL VERSION 전용 작업공간

- IDM 번역 후보를 기존 ULJM-05009 작업공간과 분리해 저장한다.
- 각 레코드에 source hash, translation, 대응 근거, 신뢰도 및 상태를 기록한다.
- 자동 대응이 확실한 항목은 `override`, 검토가 필요한 항목은 `draft` 또는 `review` 상태로 분리한다.
- 기존 106번의 XSO 190개와 IDM 11개를 기준 레코드로 포함한다.

## 5. 글리프 용량과 append-only 매핑

- 106번 mapping revision 2의 기존 339개 배정을 변경하지 않는다.
- 자동 대응 IDM 번역에 필요한 신규 한글 수를 계산한다.
- 현재 남은 안전 슬롯 95개 안에 들어가면 기존 매핑 뒤에만 추가한다.
- 95개를 초과하면 임의로 기존 글자를 교체하지 않고 다음 두 결과를 별도로 산출한다.
  - 현 안전 슬롯으로 적용 가능한 번역 부분집합
  - 전체 번역에 필요한 추가 글리프 수와 폰트 확장 후속 과제
- 글리프 선택 때문에 기존 세이브 또는 106번 매핑 코드가 바뀌지 않도록 append-only 검증을 적용한다.

## 6. IDM 패치 빌더 통합

- SPECIAL VERSION 빌더가 전용 IDM 작업공간을 읽도록 확장한다.
- 각 IDM의 문자열 길이와 후속 레코드 위치를 재계산한다.
- 독립 파일과 모든 아카이브 런타임 복사본에 동일한 결과를 넣는다.
- 독립 ISO extent와 아카이브 엔트리 할당 공간을 각각 검사한다.
- 한 건이라도 원본 hash, 대응 관계, 복사본 또는 할당 공간 검증에 실패하면 ISO 생성을 중단한다.

## 7. 2차 테스트 ISO

- 출력 경로: `patched/109-special-version-idm-dialogue-port`
- 106번에서 검증한 폰트, XSO 190개와 초반 IDM 11개를 유지한다.
- 새로 안전 대응된 IDM 번역 중 글리프 및 할당 공간 검증을 통과한 항목을 추가한다.
- 기존 SPECIAL VERSION 원본 ISO는 읽기 전용으로 유지한다.

## 검증

- 241개 IDM 파싱 및 무수정 왕복 결과를 기록한다.
- 카탈로그 레코드 수, 문자열 수, 고유 원문 수를 기록한다.
- 기존 번역 대응 방식별 성공·제외·충돌 수를 기록한다.
- 패치한 모든 IDM을 재파싱해 번역 바이트와 레코드 구조를 확인한다.
- 독립 IDM과 아카이브 복사본이 동일한지 확인한다.
- 기존 339개 글리프의 코드·폰트 인덱스·비트맵이 106번과 동일한지 확인한다.
- 수정 ISO에서 모든 대상 파일을 재추출해 작업본과 비교한다.
- ISO 허용 범위 밖 변경이 없는지 확인한다.

## 제외 범위

- 원문 및 문맥으로 안전하게 대응되지 않는 대사의 임의 번역
- SPECIAL VERSION 전용 신규 대사의 신규 번역
- 인물·몬스터명, 아이템과 시스템 메시지
- 이미지, 엔딩 영상과 XMB 이미지
- 기존 GUI의 SPECIAL VERSION 정식 지원
- 안전 슬롯을 넘어서는 실행 파일 폰트 테이블 확장

## 위험 및 중단 조건

- 일부 IDM이 다른 구조를 사용하면 해당 파일을 강제로 파싱하지 않고 형식 변형으로 분리한다.
- 동일 원문이 여러 문맥에 나타나면 자동 대응하지 않는다.
- 신규 한글이 남은 95개 안전 슬롯을 초과하면 전체 이식을 강행하지 않는다.
- IDM 재구성 결과가 할당 공간을 넘으면 해당 파일을 제외하거나 폰트 확장과 함께 후속 계획으로 분리한다.
- 기존 106번 매핑 339개 중 하나라도 변경되면 빌드를 중단한다.

## 완료 기준

- 241개 IDM 전체 카탈로그와 런타임 복사본 맵이 생성된다.
- 기존 번역과 IDM의 안전한 자동 대응 수 및 제외 사유가 확정된다.
- 106번 매핑을 보존한 상태에서 가능한 IDM 번역 부분집합이 적용된다.
- 2차 테스트 ISO가 생성되고 재추출 검증을 통과한다.
- 사용자가 여러 초·중반 IDM 장면에서 한글 출력과 게임 진행을 확인할 수 있다.
