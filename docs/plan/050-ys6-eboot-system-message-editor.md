# 050. Ys VI EBOOT 시스템 메시지 추출·편집·패치

## 상태

- 사용자 확인 완료
- 구현 및 검증 완료

## 배경

049 런타임 조사에서 장비 메뉴 안내 문구 `装備全般の設定を行います。`가 이미지가 아닌 동적 텍스트임을 확인했다. 문자열은 대사에서 사용한 CP932가 아니라 EUC-JP로 EBOOT에 저장되어 있었다.

- 현재 EBOOT 오프셋: `0x12CF34`
- 원본 ISO 오프셋: `0x33904F34`
- 런타임 메뉴 객체 주소: `0x08B50650`
- 런타임 문자열 복사 지점: `0x088D7BE4`

따라서 EBOOT의 EUC-JP 시스템 문자열을 별도 작업공간으로 관리하고, 사용자가 GUI에서 번역 상태를 편집한 뒤 기존 ISO 빌드 과정에 포함할 수 있도록 한다.

## 목표

1. 원본 복호화 EBOOT에서 시스템 메뉴용 EUC-JP 문자열 후보를 추출한다.
2. 추출 결과를 `/tools/config`의 JSON 작업공간으로 관리한다.
3. 기존 Python GUI에 시스템 메시지 편집 탭을 추가한다.
4. `override` 상태의 시스템 메시지만 EBOOT에 안전하게 적용한다.
5. 기존 대사·인물명·아이템 패치 및 폰트 생성과 하나의 ISO 빌드 과정으로 통합한다.

## 구현 계획

### 1. EUC-JP 문자열 조사 및 추출기

`/tools/scripts`에 Python 비GUI 스크립트를 작성한다.

- 원본 복호화 EBOOT에서 유효한 EUC-JP 문자열 연속 구간 탐색
- 파일 오프셋, 원본 바이트, 원문, 할당 길이 기록
- ASCII 전용 데이터와 우연히 EUC-JP로 해석되는 바이너리를 줄이기 위한 일본어 문자 포함 조건 적용
- 알려진 문구 `装備全般の設定を行います。`가 `0x12CF34`에서 추출되는지 기준점 검증
- 메뉴 안내 문구 후보를 검토할 수 있도록 주변 오프셋과 안정적인 식별자 생성

초기 추출 범위는 EBOOT 전체로 하되, 자동 패치 대상은 사용자가 `override`로 승인한 레코드로 제한한다.

### 2. 시스템 메시지 JSON 작업공간

기본 파일을 `/tools/config/system-messages.json`에 둔다.

레코드에는 최소한 다음 정보를 기록한다.

- 안정적인 식별자
- EBOOT 파일 오프셋
- 원본 EUC-JP 바이트와 SHA-256 검증 정보
- 원문
- 한글 번역
- 상태: `untranslated`, `draft`, `override`, `conflict`
- 원본 할당 바이트 길이
- 메모 또는 화면 분류

원본 위치와 바이트가 일치하지 않으면 빌드를 중단하여 다른 EBOOT에 잘못 적용하지 않도록 한다.

### 3. GUI 시스템 메시지 탭

사용자 실행 GUI인 `/tools/ys6_dialogue_viewer.py`에 `시스템 메시지` 탭을 추가한다.

- 실행 시 `/tools/config/system-messages.json` 자동 로드
- 원문·번역·상태·오프셋 검색 및 필터
- 여러 항목 선택 후 일괄 `override` 변경
- 저장 전 구조·중복 오프셋·바이트 길이 검증
- 원본 허용 공간을 넘는 번역은 눈에 띄게 표시하고 `conflict` 처리
- 기존 대사/인물명/아이템 탭 동작은 유지

### 4. 한글 인코딩과 고정 길이 패치

- 한글은 기존 `mapping.json` 및 EBOOT 글리프 매핑 체계를 사용해 게임용 2바이트 코드로 변환한다.
- 시스템 메시지 번역에 새로 필요한 한글도 폰트 글리프 생성 대상에 포함한다.
- 번역 바이트가 원본 할당 공간 이내인 경우에만 제자리 패치한다.
- 남는 공간은 문자열 종료와 원본 구조를 해치지 않는 방식으로 0 바이트 처리한다.
- 공간을 초과하는 항목은 자동으로 잘라내지 않고 빌드를 실패시키며 GUI에서 교정하도록 한다.
- EBOOT 폰트 패치 후 검증된 시스템 문자열 패치를 적용하여 두 변경이 함께 유지되게 한다.

문자열 재배치나 코드 포인터 수정은 이번 범위에서 제외한다. 고정 공간을 넘는 문구가 실제로 필요하면 별도 계획으로 다룬다.

### 5. 기존 패치 빌드 통합

- `/tools/scripts/ys6_patch_builder.py`가 시스템 메시지 작업공간을 기본 입력으로 검사한다.
- `/tools/scripts/ys6_integrated_build.py`가 `override` 항목만 EBOOT에 반영한다.
- preflight와 build 결과에 적용 수, 오프셋, 원문, 번역, 원본/결과 바이트를 기록한다.
- 결과 매니페스트에 시스템 메시지 작업공간 경로와 해시를 기록한다.
- GUI의 `패치 빌드` 탭에서 별도 명령 없이 함께 적용되게 한다.

## 검증 계획

1. 추출기가 `装備全般の設定を行います。`를 EBOOT `0x12CF34`에서 찾는지 확인한다.
2. 작업공간을 저장 후 다시 읽었을 때 모든 필드가 보존되는지 확인한다.
3. 알려진 문구 하나를 짧은 한글 문구로 `override`하여 preflight를 통과하는지 확인한다.
4. 원본 바이트 불일치 및 공간 초과 역테스트가 각각 실패하는지 확인한다.
5. 빌드된 EBOOT에서 해당 오프셋의 바이트와 종료 처리를 확인한다.
6. 기존 대사·인물명·아이템 설정을 포함한 통합 preflight를 실행한다.
7. Python 구문 검사와 관련 스크립트 자체 검증을 수행한다.
8. 실제 ISO 생성과 PPSSPP 화면 확인은 구현 검증 후 사용자 확인을 받아 진행한다.

파일명과 세부 함수 구성은 구현 중 기존 모듈 구조에 맞춰 조정할 수 있으며, 범위가 달라지는 경우 계획 문서를 먼저 갱신한다.

## 제외 범위

- 시스템 메시지의 실제 한글 번역 일괄 작성
- 원본 공간을 넘는 문자열의 재배치 및 EBOOT 코드/포인터 수정
- 메뉴 제목이나 버튼에 포함된 이미지 번역
- 이번 계획 확인 전 구현 및 ISO 생성

## ROM 처리

- 원본 ISO는 읽기 전용 입력으로 사용한다.
- 구현 단계에서는 우선 preflight와 작업 EBOOT로 검증한다.
- 실제 수정 ISO는 사용자가 별도로 확인한 뒤 `/patched` 아래 기존 Ys VI 작업 폴더에 생성한다.
- 불필요한 테스트 ISO를 매 단계마다 새로 만들지 않는다.
