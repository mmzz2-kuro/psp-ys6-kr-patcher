# 040. 남은 제어문자 불일치 40개 검토표

## 목적

전체 draft 가상 승격 검사에서 남은 제어문자 불일치 40개를 사용자가 검토하고 처리 방침을 정하기 위한 문서다. 이번 문서 작성에서는 번역 데이터와 ISO를 변경하지 않는다.

## 검토 방법

- `원문 줄 수에 맞춰 재배치`: 번역의 의미는 유지하고 `\n` 개수와 위치만 PSP 원문 구조에 맞춘다.
- `3줄 유지 여부 확인`: 한국어 가독성을 위해 원문보다 한 줄을 더 사용한 항목이다. 화면에서 3줄이 안전하면 별도 허용하고, 그렇지 않으면 2줄로 줄인다.
- `문장 경계 재분할`: Windows판과 PSP판의 레코드 경계가 달라 번역 내용이 인접 레코드로 넘어간 항목이다. 두 레코드를 한 쌍으로 다시 번역해야 한다.
- 검토 결과 열에 `원문 맞춤`, `현재 유지`, `직접 수정` 중 하나를 기록할 수 있다.

## 선택 가능한 처리 정책

### 정책 A: 원문 줄 수 엄격 유지

- 36개의 일반 항목을 모두 원문과 같은 `\n` 개수로 교정한다.
- 검증 규칙을 추가하지 않아도 된다.
- 한국어 문장이 긴 일부 항목은 화면 폭이 빡빡할 수 있다.

### 정책 B: 한국어 줄바꿈 재배치 허용

- 3줄 유지 후보와 원문에 없던 줄바꿈 후보를 화면 가독성 기준으로 유지한다.
- 레코드별 `allow_linebreak_reflow`를 추가한다.
- `\x1` 등 다른 제어 토큰 차이는 계속 차단한다.
- 줄 수 상한과 줄별 표시 폭 검사가 함께 필요하다.

### 권장안

- 문장 경계 4개는 반드시 다시 분할한다.
- 원문보다 줄바꿈이 적은 항목은 우선 원문 줄 수에 맞춘다.
- 위 3줄 유지 후보 9개와 원문 0줄→번역 1줄인 5개는 화면 폭을 기준으로 사용자가 유지 여부를 정한다.
- `allow_linebreak_reflow`는 사용자가 유지하기로 한 항목에만 제한적으로 설정한다.

## 추가 계획: 잔여 항목 `conflict` 표시

검색 편의를 위해 현재 작업공간을 다시 검증했을 때 실제로 제어문자 불일치가 남아 있는 레코드만 `draft`에서 `conflict`로 변경한다.

### 적용 규칙

- 문서의 과거 40개 목록을 그대로 상태 변경하지 않는다.
- 사용자가 이미 수정하여 검증을 통과한 11개는 `draft`로 유지한다.
- 현재도 실패하는 29개만 `conflict`로 변경한다.
- 상태 변경 전 작업공간을 `.work/ys6-control-conflict-review`에 백업한다.
- 각 레코드의 번역문과 메타데이터는 변경하지 않는다.
- notes에 `control-linebreak review 040` 표식을 추가한다.
- 수정이 끝난 항목은 사용자가 GUI에서 `draft` 또는 `override`로 바꿀 수 있다. `override` 전환 시 기존 검증을 반드시 통과해야 한다.

### 안전성

- `conflict`는 패치 빌드 대상인 `override`가 아니므로 미검토 항목이 ISO에 들어가는 것을 막는다.
- 이후 재검사 스크립트로 해결된 conflict와 아직 남은 conflict를 구분할 수 있게 한다.
- ISO는 생성하거나 수정하지 않는다.
