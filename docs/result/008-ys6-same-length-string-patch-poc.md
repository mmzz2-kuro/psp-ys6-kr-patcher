# Ys VI 동일 길이 문자열 수정 파이프라인 PoC 결과

## 상태

- 완료
- 사용자 승인: 2026-08-11

## 결론

일반 NPC 대사의 본문 문자열 하나를 같은 CP932 바이트 길이로 교체하고, XSR 재조립→`.z` 재압축→재해제→XSR 재검증까지 연결한 수정 파이프라인 PoC가 성공했다. 원본 ISO에는 쓰지 않았다.

## 대상

- ISO 내부 파일: `PSP_GAME/USRDIR/data/map/s_00/s_0000/talkkebin.xso.z`
- XSR 문자열 인덱스: 4
- opcode 참조: `100502 arg3` 본문 문자열
- 원문: `ここで何をしているかだって？`
- 시험 문구: `これは動作確認用の文章です。`
- 원문 CP932 길이: 28바이트
- 시험 문구 CP932 길이: 28바이트
- 개행·변수·색상·루비 토큰 없음

## 구현

`/tools/scripts/ys6_xso.py`에 제한적인 `replace` 명령을 추가했다.

```powershell
python tools\scripts\ys6_xso.py replace input.xso 4 "これは動作確認用の文章です。" output.xso --json
```

안전장치:

- 새 텍스트 CP932 인코딩 필수
- 원본과 새 텍스트의 CP932 바이트 길이 일치 필수
- 문자열 인덱스 범위 검사
- 문자열 수와 순서 보존
- 헤더 및 바이트코드 보존
- 기존 출력 덮어쓰기 거부
- 출력 XSR 즉시 재파싱 검증

## ISO 9660 배치 조사

읽기 전용 `/tools/scripts/iso9660_info.py`를 추가해 대상 파일의 extent와 디렉터리 레코드를 확인했다.

| 항목 | 값 |
|---|---:|
| 시작 LBA | 156,320 |
| ISO 내 데이터 바이트 오프셋 | 320,143,360 |
| 논리 파일 크기 | 538바이트 |
| 할당 섹터 | 1 |
| 할당 바이트 | 2,048바이트 |
| 원본 마지막 섹터 여유 | 1,510바이트 |
| 수정본 배치 후 여유 | 1,499바이트 |
| 디렉터리 레코드 바이트 오프셋 | 501,018 |
| 크기 LE 필드 오프셋 | 501,028 |
| 크기 BE 필드 오프셋 | 501,032 |

### 판정

- 수정 `.z` 549바이트는 기존 한 섹터 안에 충분히 들어간다.
- 시작 LBA와 후속 파일 배치를 변경할 필요는 없다.
- 그러나 ISO 9660 논리 크기가 538바이트이므로 데이터만 덮으면 수정본 마지막 11바이트가 읽히지 않는다.
- ISO 사본 적용 시 디렉터리 레코드의 LE/BE 데이터 길이 필드를 모두 549로 갱신해야 한다.
- 같은 섹터에 남는 기존 바이트는 새 파일 끝 이후를 0으로 정리하는 정책이 안전하다.
