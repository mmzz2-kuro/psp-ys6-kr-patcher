# 101. Ys VI 기존 원본판 아날로그 스틱 지원 가능성 조사 결과

상태: 완료

## 결론

- 기존판 `ULJM-05009`에 아날로그 스틱 지원을 활성화하는 것은 **비교적 어렵지 않게 가능할 것으로 판단된다.**
- 기존판에도 이미 아날로그 축을 읽고 이동용 실수 값으로 변환하는 코드가 들어 있다.
- 실제 차이는 여러 상태 전환 과정에서 기존판이 PSP 입력 샘플링 모드를 `디지털(0)`로 되돌리는 반면, SPECIAL VERSION은 같은 지점에서 `아날로그(1)`을 유지한다는 점이다.
- 기존판의 8개 MIPS 명령을 변경하는 최소 패치 시안을 생성했으며 정적 검증을 통과했다.
- 전체 이동 루틴이나 SPECIAL VERSION 코드를 통째로 이식할 필요는 없어 보인다.

## 확인된 입력 구조

두 버전 모두 다음 PSP 컨트롤러 API를 사용한다.

- `sceCtrlSetSamplingCycle`
- `sceCtrlSetSamplingMode`
- `sceCtrlReadBufferPositive`

두 버전 모두 초기화 시 다음과 같이 아날로그 모드를 설정한다.

```text
sceCtrlSetSamplingCycle(0)
sceCtrlSetSamplingMode(1)
```

기존판의 입력 읽기 함수도 `SceCtrlData`의 다음 값을 이미 처리한다.

- 버튼: 구조체 `+4`
- `Lx`: 구조체 `+8`
- `Ly`: 구조체 `+9`

`Lx`, `Ly`에서 중심값 `128`을 빼고 부동소수점 이동 값으로 변환해 내부 입력 상태에 저장한다. 따라서 축 처리 자체를 새로 구현할 필요가 없다.

## 기존판과 SPECIAL VERSION의 핵심 차이

- 초기화 직후에는 두 버전 모두 아날로그 모드 `1`을 사용한다.
- 이후 게임 상태 전환 8곳에서 기존판은 `sceCtrlSetSamplingMode(0)`을 호출한다.
- SPECIAL VERSION의 대응 지점은 모두 `sceCtrlSetSamplingMode(1)`을 호출한다.

기존판의 다음 명령을 변경하면 SPECIAL VERSION과 같은 모드 유지 동작이 된다.

```text
기존: addu  a0, zero, zero  # mode 0
변경: addiu a0, zero, 1     # mode 1
```

## 검증 결과

- 복호화 EBOOT 크기 1,935,840바이트 유지
- 변경 명령 수: 8개
- 실제 변경 바이트 수: 32바이트
- 승인된 8개 명령 외 변경 없음
- 출력 파일 재검증 통과
- 현재 한글 패치 빌드 EBOOT에서도 8개 위치가 원본 명령 그대로여서 폰트·시스템 메시지 패치와 충돌하지 않음
- 원본 ISO와 기존 한글 패치 ISO는 이번 조사에서 수정하지 않음

## 데드존 차이

- SPECIAL VERSION은 아날로그 축의 원점 거리 제곱을 계산해 `0x1000` 미만이면 중립으로 처리한다.
- 이는 반경 약 64에 해당하는 데드존이다.
- 기존판 입력 함수에는 같은 데드존 코드가 없지만, 축 변환과 이동 값 저장은 이미 구현돼 있다.
- 우선 최소 8명령 패치로 실기 동작을 확인하는 것이 좋다.
- 캐릭터가 중립 상태에서 움직이는 드리프트가 발생하면 데드존 로직을 추가로 이식해야 한다.

## 예상 동작과 시험 항목

최소 패치가 의도대로 작동하면 다음 결과가 예상된다.

- 방향키 조작은 기존처럼 유지
- 필드 이동에서 아날로그 방향 입력 활성화
- 대각선과 연속 방향 입력 가능
- 게임 상태가 바뀐 뒤에도 아날로그 모드 유지

실기 또는 PPSSPP에서 다음 항목을 확인해야 한다.

1. 필드 이동
2. 대각선 이동
3. 아날로그 중립 복귀와 드리프트
4. 맵 이동·전투·이벤트 이후에도 입력 유지
5. 메뉴와 대화 선택에서 의도하지 않은 연속 입력 여부
6. 방향키와 아날로그 동시 입력
