# 100. Ys VI SPECIAL VERSION 한글 패치 이식 구조·난이도 조사 결과

상태: 완료

## 결론

- `ULJM-05155 SPECIAL VERSION`으로 한글 패치를 이식하는 것은 **기술적으로 가능성이 높다.**
- 그러나 기존 패치 파일을 경로만 바꿔 넣는 작업은 아니며, 실행 파일·대사 매핑·이미지 좌표를 상당 부분 다시 조사해야 한다.
- 압축 컨테이너, XSO와 아카이브 형식은 기존 도구를 재사용할 수 있어 완전한 신규 분석보다는 수월하다.
- 전체 난이도는 **높음**이다. 특히 EBOOT 한글 폰트 이식과 대사 재매핑이 핵심 병목이다.
- 현실적인 방법은 `EBOOT·폰트 → 일반 대사 → 인물·아이템 → 이미지 → 영상` 순서의 단계별 이식이다.

## 실행 파일

- 두 버전의 `BOOT.BIN`은 모두 `7F 45 4C 46`으로 시작하는 분석 가능한 ELF이다.
- 두 버전의 `EBOOT.BIN`은 모두 `~PSP` 암호화 컨테이너이다.
- SPECIAL VERSION의 복호화 실행 파일 역할은 ISO의 `BOOT.BIN`으로 조사할 수 있다.

| 항목 | ULJM-05009 | ULJM-05155 |
|---|---:|---:|
| `BOOT.BIN` | 1,935,501바이트 | 2,070,916바이트 |
| `EBOOT.BIN` | 1,935,840바이트 | 2,071,264바이트 |

- 실행 파일 크기와 코드가 다르므로 기존 폰트 아틀라스·시스템 메시지·코드 패치 오프셋을 재사용할 수 없다.
- 다만 새 `BOOT.BIN`이 ELF이므로 기존 패치 함수와 데이터 시그니처를 기준으로 새 위치를 다시 찾을 수 있다.
- 난이도: **매우 높음**. 이 단계가 성공해야 게임 전체 한글 표시가 가능하다.

## 아카이브와 핵심 데이터

- 새 버전의 아카이브 699개 중 698개가 기존 `ys6_arc` 파서로 정상 분석됐다.
- 아카이브 안에서 XSO 컨테이너 2,013개를 확인했다.
- 독립 파일까지 합쳐 새 버전 XSO 후보 3,458개를 정상 해제했다.
- 기존 `ys6_z` 압축 해제·재압축과 `ys6_arc` 교체 로직을 그대로 활용할 수 있다.

`init.bin`은 기존 1,570,816바이트에서 새 버전 288,768바이트로 작아졌다. 새 버전은 다음 핵심 데이터를 `.z`로 압축해 저장한다.

- `castinfo.dat.z`
- `enemyinfo.dat.z`
- `invinfo.dat.z`
- `gameinfo.dat.z`
- `eex.dat.z`

다섯 컨테이너 모두 정상 해제됐다. `castinfo`, `enemyinfo`, `gameinfo`, `eex`는 해제 크기가 기존과 같지만 내용은 다르다. `invinfo`는 13,448바이트에서 14,184바이트로 늘어 항목 또는 구조가 추가된 것으로 보인다.

- 인물·몬스터명: 레코드 크기 검증 후 기존 번역을 대응시킬 가능성이 높음
- 아이템: 새 항목과 인덱스를 다시 조사해야 함
- 난이도: **중간~높음**

## 대사 이식률

기존 대사 카탈로그 1,194개 XSO와 번역 레코드 7,424개를 새 버전의 독립·아카이브 XSO 전체와 비교했다.

### 파일 구조 기준

| 분류 | XSO 파일 | 번역 레코드 |
|---|---:|---:|
| payload 완전 동일 | 23 | 205 |
| 코드와 문자열 수 동일 | 487 | 964 |
| 직접 구조 대응 실패 | 684 | 6,255 |

구조 기준으로 바로 이식하거나 인덱스 검토 후 이식 가능한 레코드는 1,169개, 약 15.7%이다.

### 일본어 원문 기준

| 분류 | 번역 레코드 |
|---|---:|
| 한 위치에 고유하게 대응 | 880 |
| 여러 런타임 복사본에서 같은 인덱스로 대응 | 1,033 |
| 여러 인덱스 후보로 모호함 | 102 |
| 같은 파일명 후보에서 원문을 찾지 못함 | 5,409 |

- 원문 기준으로 안전하게 자동 또는 반자동 대응 가능한 항목은 최소 1,913개, 약 25.8%이다.
- 5,409개는 파일명 변경, 이벤트 재편집, 문자열 병합·분할 또는 원문 수정 여부를 문맥 기반으로 다시 조사해야 한다.
- 기존 한글 번역 문장 자체는 재사용할 수 있지만 새 카탈로그와 인덱스 매핑을 새로 만드는 작업량이 크다.
- 난이도: **높음**

## 이미지 자산

현재 추가 이미지 manifest의 49개 리소스를 비교했다.

- 압축 해제 payload까지 동일: 2개
- 압축 해제 payload가 다름: 46개
- 새 버전의 동일 경로가 없음: 1개
- 옵션 메뉴 `static_tex.dds.z`도 내용이 다르다.

따라서 기존 한글 PNG는 번역·디자인 원본으로 재사용할 수 있지만, 새 버전 텍스처의 좌표, 블록 오프셋과 런타임 아카이브 복사본을 다시 추출해야 한다. 기존 manifest를 그대로 사용할 수는 없다.

- 난이도: **높음**, 단 이미지 제작 작업 자체는 상당 부분 재사용 가능

## 엔딩 영상

SPECIAL VERSION의 두 대상 PMF도 현재 PMF 파서로 정상 분석됐다.

| 영상 | 기존 프레임 | 새 버전 프레임 | 기존 크기 | 새 버전 크기 |
|---|---:|---:|---:|---:|
| `im03a_kaizoku.pmf` | 2,458 | 2,479 | 11,786,240 | 11,964,416 |
| `im03b_kazaminooka.pmf` | 2,278 | 2,307 | 10,774,528 | 11,100,160 |

- 영상 길이와 GOP/AU 배치가 달라 기존 한글 PMF를 그대로 넣을 수 없다.
- 기존 자막 문구와 조판 자산은 재사용할 수 있지만 새 영상 기준으로 타임라인을 조정하고 다시 인코딩·PMF 재구성해야 한다.
- PMF 구조 분석과 재구성 도구는 재사용 가능하다.
- 난이도: **중간**

## XMB 이미지

- SPECIAL VERSION은 별도의 `PIC0.PNG`, `PIC1.PNG`, `ICON0.PNG`을 사용한다.
- `PIC0.PNG` 크기도 기존 56,082바이트와 달리 66,292바이트이다.
- SPECIAL VERSION 표기를 보존하려면 새 원본을 기준으로 별도 한글 이미지를 만들어야 한다.
- 난이도: **낮음**

## 왕복 시험

- 새 버전 독립 `talkoruha3.xso.z`를 해제·재압축하고 payload가 일치함을 확인했다.
- 재압축 크기도 원본과 같은 1,250바이트였다.
- `xso0202.bin`의 `talkoruha3.xso.z` 엔트리를 같은 데이터로 교체한 결과 아카이브 전체가 바이트 단위로 동일했다.
- 새 `static_tex.dds.z`도 해제·재압축 후 payload와 크기가 원본과 일치했다.
- 즉, 새 버전의 기본 컨테이너 재구성 기술은 이미 확보돼 있다.

## 권장 이식 순서

1. SPECIAL VERSION 전용 작업공간과 원본 해시를 별도로 만든다.
2. 새 `BOOT.BIN`에서 한글 폰트 아틀라스, 문자 매핑과 시스템 문자열을 재탐색한다.
3. 새 XSO 카탈로그와 런타임 아카이브 맵을 생성한다.
4. 확실한 1,169개 구조 대응 레코드부터 이식해 게임 내 출력 시험을 한다.
5. 원문 고유 대응과 문맥 정렬로 나머지 번역을 단계적으로 이식한다.
6. `castinfo.dat.z`, `enemyinfo.dat.z`, `invinfo.dat.z` 전용 패처를 만든다.
7. 새 이미지 원본을 다시 추출해 기존 한글 PNG를 새 좌표에 맞춰 적용한다.
8. 마지막으로 엔딩 영상과 XMB 이미지를 별도 재구성한다.
9. 기존 ULJM-05009와 SPECIAL VERSION 빌드 프로필을 GUI에서 명확히 분리한다.

## 종합 난이도

| 구성 | 난이도 | 기존 작업 재사용성 |
|---|---|---|
| EBOOT·폰트·시스템 메시지 | 매우 높음 | 번역과 분석 방법 재사용, 오프셋 재조사 |
| 일반 대사 | 높음 | 번역문 재사용, 매핑 대규모 재작성 |
| 인물·몬스터명 | 중간 | 번역 재사용, 압축 컨테이너 대응 추가 |
| 아이템 | 중간~높음 | 번역 재사용, 새 구조·항목 조사 |
| 옵션·추가 이미지 | 높음 | 한글 PNG 재사용, 좌표·복사본 재조사 |
| 엔딩 영상 | 중간 | 자막·도구 재사용, 영상별 재인코딩 |
| XMB 이미지 | 낮음 | 조판 방식 재사용 |

전체적으로 기존 패치 개발의 단순 복사는 아니지만, 파서·압축·ISO 패치·GUI 기반이 이미 있어 **처음부터 다시 만드는 것보다는 분명히 유리하다.** 가장 먼저 EBOOT 한글 폰트 이식 가능성을 입증하는 작은 시험을 진행하는 것이 합리적이다.

## 안전 및 알려진 사항

- 두 원본 ISO는 수정하지 않았다.
- 이번 조사에서는 전체 패치 ISO나 테스트 ISO를 생성하지 않았다.
- 원문 미대응 5,409개는 신규 번역이 반드시 필요하다는 뜻이 아니라, 현재 자동 기준만으로 안전한 대응을 확정하지 못했다는 뜻이다.
- 실제 이식을 시작하려면 EBOOT·폰트 검증을 별도 계획으로 먼저 수행해야 한다.
