# 056. Ys VI 추가 이미지 편집·재삽입 및 GUI 빌드 연동 결과

## 결과

- 055에서 찾은 이미지 리소스 11종을 GUI 패치 ISO 빌드에 연결했다.
- 사용자가 수정할 수 있는 문구별 PNG 조각 39개를 생성했다.
- 원본 ISO는 수정하지 않았다.

## 구현 내용

- `tools/scripts/ys6_additional_image_patch.py`
  - 편집 조각 생성 및 유효성 검사
  - 편집 RGBA 픽셀의 직접 복사
  - 변경된 4×4 압축 블록만 재인코딩
  - DXT1 고품질 RGB565 탐색 재사용
  - DXT3 명시적 4비트 알파 보존
  - 컨테이너 재압축·왕복·할당 크기 검사
- `tools/scripts/ys6_integrated_build.py`
  - 추가 이미지 독립 파일을 ISO 교체 목록에 포함
  - `saveicon2`, `itemcursor`, `itemwin`의 `static_tex` 내장 사본 동기화
- `tools/scripts/ys6_patch_builder.py`
  - 추가 이미지 경로·편집 파일 개수 검사 및 빌드 인자 연결
- `tools/ys6_dialogue_viewer.py`
  - 패치 빌드 탭에 `추가 이미지 폴더` 버튼과 편집 이미지 개수 표시 추가
- `tools/patchdata/ys6_additional_images`
  - `source_parts`: 원본 조각 39개
  - `edited_parts`: 사용자가 같은 상대 경로로 편집본을 넣는 폴더
  - 스키마 2 매니페스트에 조각 좌표·크기 기록

## 검증

- Python 구문 검사 통과:
  - 추가 이미지 처리기
  - 통합 빌드
  - 사용자 패치 빌더
  - GUI
- 패치 데이터 일반 검사 통과: 추가 편집 이미지가 없을 때 `0`개로 정상 인식한다.
- DXT1 단일 픽셀 역테스트:
  - `save_confirmations` 변경 블록 1개
  - 재압축 크기 14,422바이트, 할당 여유 1,962바이트
- DXT3 단일 픽셀 역테스트:
  - `place_names_00` 변경 블록 1개
  - 재압축 크기 8,790바이트, 할당 여유 1,450바이트
- 내장 사본 역테스트:
  - `static_tex.dds.z` 그림 index 69 변경 블록 1개
  - 전체 페이로드 크기 유지
- 실제 통합 사전검사 통과:
  - 추가 이미지 1개 인식
  - 독립 파일과 내장 사본 동시 처리
  - 할당 공간 초과 없음
- 테스트용 편집 PNG는 사전검사 후 제거했으며 `edited_parts`는 사용자 작업 입력만 받는 상태다.

## 사용 방법

1. GUI의 `패치 빌드` 탭에서 `추가 이미지 폴더`를 연다.
2. `source_parts`의 필요한 PNG를 참고한다.
3. 수정본을 `edited_parts` 아래 동일 리소스 폴더와 파일명으로 저장한다.
4. `데이터 다시 읽기`로 개수를 확인하고 `사전 검증`을 실행한다.
5. 검증이 통과하면 패치 ISO를 생성한다.

## 알려진 제한

- 월드맵은 지명별 분리가 아니라 전체 320×240 이미지 편집 단위다.
- 분할 조각은 배경을 포함한다. 원본 조각과 정확히 같은 크기로 저장해야 한다.
- 실제 한글 이미지 디자인 및 게임 화면별 육안 검수는 후속 작업이다.
