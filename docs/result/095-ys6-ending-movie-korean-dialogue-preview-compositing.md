# 095. Ys VI 엔딩 영상 한글 대화창 합성 미리보기 결과

## 결과

- 두 엔딩 PMF의 대화창에 094번 한글 화자명과 교정 대사를 합성한 MP4 미리보기를 생성했다.
- 일본어 이름과 본문의 밝은 글자 픽셀 및 외곽선을 대화창 내부에서 프레임별로 복원한 뒤 한글을 렌더링했다.
- 초상화, 금색 대화창 테두리, 오른쪽 원형 장식과 영상 배경은 마스크 영역에서 제외했다.
- 밝은 장면이 대화창 페이드 사이로 보이는 프레임에서는 배경을 글자로 오인하지 않도록 합성을 제한했다.
- 최초 시안에서 `im03b` 3번 종료 페이드가 대표 프레임으로 잘못 선택된 문제를 수정하고, 대화창이 안정적으로 표시된 프레임만 대표 이미지로 선택했다.

## 출력 영상

- `tools/patchdata/work/current/095-ending-movie-korean-preview/im03a_kaizoku-korean-preview.mp4`
  - H.264, 480×272, `30000/1001`fps, 2,458프레임
- `tools/patchdata/work/current/095-ending-movie-korean-preview/im03b_kazaminooka-korean-preview.mp4`
  - H.264, 480×272, `30000/1001`fps, 2,278프레임

현재 도구가 원본 PMF에서 인식하는 별도 오디오 스트림은 없으므로 MP4도 비디오 전용이다.

## 렌더링 설정

- 글꼴: `C:\Windows\Fonts\malgun.ttf`
- 화자명 크기: 12px
- 본문 크기: 15px
- 본문 줄 간격: 22px
- 화자명 영역: `(124, 170)~(350, 188)` — 상단 경계를 최초 시안보다 3px 축소
- 본문 영역: `(124, 191)~(430, 252)` — 상단 경계를 최초 시안보다 2px 축소
- 한글 화자명 시작 좌표: `(132, 172)` — 최초 시안보다 아래로 4px 조정
- 한글 본문 시작 좌표: `(130, 195)` — 최초 시안보다 아래로 4px 조정
- 글자색: 밝은 회백색
- 외곽선: 어두운 1px

사용자 검수 의견에 따라 화자명과 본문을 모두 4px 아래로 이동한 버전으로 MP4와 검수 이미지를 다시 생성했다. 마스크와 타임라인은 그대로 유지했다.

후속 검수에서 마스크가 위쪽 영역을 침범하는 느낌을 줄이기 위해 두 마스크의 위쪽 2px를 제외하고 다시 생성했다. 출력 좌표와 타임라인은 변경하지 않았다.

상단 마스크 축소 후 해적선 9번의 종료 페이드가 대표 프레임으로 선택되는 현상을 발견해 대화창 안정 판정 평균 밝기를 `48` 미만에서 `46` 미만으로 강화했다.

추가 검수 의견에 따라 화자명 마스크의 위쪽 경계를 `y=169`에서 `y=170`으로 1px 더 축소했다. 본문 마스크와 한글 출력 위치는 유지했다.

PMF 재구성 후 디코딩 검수에서 일부 종료 페이드에 일본어가 남는 것을 확인했다. 각 대사의 안정 프레임에서 화자명·본문 글자 모양 마스크를 고정 추출해 전환 프레임에도 같은 작은 영역만 복원하고, 한글은 대화창 평균 밝기로 계산한 투명도에 맞춰 페이드하도록 보강했다.

## 검증

- 두 MP4를 `ffprobe`로 검사해 H.264, 480×272, `30000/1001`fps인지 확인했다.
- 출력 프레임 수가 원본 디코딩 프레임 수인 2,458개와 2,278개로 유지되는지 확인했다.
- 15개 대표 프레임과 접촉 시트를 육안 확인했다.
- 모든 대표 프레임에서 한글 화자명과 본문이 식별되며 일본어 본문이 제거된 것을 확인했다.
- 두 줄 문장이 오른쪽 장식과 초상화를 침범하지 않는 것을 확인했다.
- 합성 스크립트를 `python -m py_compile`로 검사했다.

## 알려진 사항

- 이 출력은 위치와 가독성 검수용 MP4이며 PSP용 PMF가 아니다.
- 대화창이 열리거나 닫히는 밝은 페이드 프레임은 배경 손상을 막기 위해 합성을 건너뛴다. 이 구간에는 원래 글자도 매우 희미하지만 최종 PMF 단계 전 실제 재생 화면에서 전환감을 확인해야 한다.
- 맑은 고딕은 시스템 글꼴이므로 최종 배포 파이프라인에서는 글꼴 라이선스와 실행 환경 의존성을 고려해 프로젝트용 글꼴을 지정해야 한다.
- MP4는 손실 압축이므로 비대사 프레임의 디코딩 픽셀이 원본과 완전히 동일하지는 않다. 합성 처리 단계에서는 대사 대상 밖 프레임을 변경하지 않았다.
