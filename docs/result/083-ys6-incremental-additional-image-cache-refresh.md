# 083. Ys VI 추가 이미지 캐시 증분 갱신 결과

## 수행 내용

- 추가 이미지 캐시 갱신을 전체 재압축 방식에서 리소스 단위 증분 방식으로 변경했다.
- 원본 컨테이너, 리소스 정의 및 적용 PNG의 SHA-256을 기존 캐시와 비교한다.
- 변경되지 않은 캐시 컨테이너는 실제 파일 SHA-256을 확인한 뒤 임시 캐시로 복사한다.
- PNG 또는 정의가 변경된 리소스, 신규 리소스 및 손상된 캐시만 다시 압축한다.
- 현재 매니페스트에서 제거된 과거 캐시는 새 캐시에서 제외한다.
- 변경이 없으면 캐시 디렉터리를 교체하지 않고 즉시 완료한다.
- 갱신이 필요할 때는 기존과 동일하게 임시 디렉터리 전체 검증 후 원자적으로 교체한다.
- 실패 시 기존 정상 캐시를 그대로 보존한다.

## GUI 변경

- 기존 `이미지 캐시 갱신` 버튼의 사용법은 그대로 유지했다.
- 갱신 전에 다음 항목을 로그에 표시한다.
  - 재사용 리소스 수
  - 재압축 리소스 수
  - 신규 리소스 수
  - 제거 리소스 수
  - 실제 재압축 및 신규 대상 ID
- 진행률은 실제 압축 대상 수를 기준으로 표시한다.
- 완료 로그에 재사용·재압축·신규·제거 수, 전체 크기 및 소요 시간을 표시한다.
- 변경이 없으면 `이미지 캐시가 이미 최신입니다`라고 안내한다.

## 실제 변경 이미지 검증

사용자가 수정한 다음 이미지를 실제 대상으로 사용했다.

- `edited_parts/boss_names_00/line_04.png`

첫 증분 갱신 결과:

- 재사용: 35개
- 재압축: 1개
- 신규: 0개
- 제거: 0개
- 재압축 대상: `boss_names_00`
- 갱신 시간: 2.376초
- 전체 캐시: 36개, 818,946바이트
- 새 `boss_names_00` 컨테이너: 4,373/8,192바이트

따라서 사용자가 수정한 `line_04.png`가 속한 `boss_names_00`만 다시 압축됐다.

## 사용 방법

1. 추가 이미지 PNG를 수정하고 저장한다.
2. GUI에서 원본 ISO를 선택한다.
3. `이미지 캐시 갱신`을 누른다.
4. GUI 로그에서 재압축 대상과 개수를 확인한다.
5. 갱신 완료 후 사전 검증 또는 패치 ISO 생성을 실행한다.

한 리소스에 PNG 조각이 여러 개 있으면 그중 하나만 바뀌어도 해당 리소스 하나가 다시 압축된다. 다른 리소스는 재사용된다.

## ROM 및 임시 파일

- 이번 작업에서는 새 테스트 ISO를 생성하지 않았다.
- 사용자가 변경한 `boss_names_00/line_04.png`는 갱신된 캐시에 반영됐으며 다음 GUI ISO 생성에서 사용된다.
- 원본 ISO와 기존 082 테스트 ISO는 변경하지 않았다.
- 신규·제거·손상·실패·전체 재생성 검증은 임시 복사 작업공간에서 수행하고 정리했다.
