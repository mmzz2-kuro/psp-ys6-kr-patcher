# 038. 전체 draft 한글패치 적용 위험 분석 결과

## 결론

현재 `draft` 4,628개를 그대로 모두 `override`로 바꾸면 한글패치를 빌드할 수 없다.

직접 적용 시 작업공간 검증에서 406개 오류가 발생하고, 이 오류를 제외해도 런타임 대응, 공유 XSO 충돌 및 미지원 문자 문제로 빌드가 순차적으로 중단된다. 문제 항목 589개를 제외한 최대 호환 집합 4,039개는 전체 통합 `preflight`를 통과했다.

따라서 다음처럼 판단한다.

- 4,628개 전체 즉시 적용: 불가능
- 기술적 blocker 589개 제외 후 4,039개 적용: 빌드 가능
- 4,039개 무검수 적용: 가능하지만 권장하지 않음
- 권장 방식: blocker를 자동 정규화·대응한 뒤 위험 항목을 검수하고 단계적으로 적용

## 직접 적용을 막는 문제

### 1. 제어 토큰 및 마크업 오류 — 402개 레코드

전체 draft를 override로 바꾼 복사본은 다음 검증 오류를 냈다.

- 제어 토큰 불일치: 308건
- 마크업 불일치: 98건
- 두 오류가 동시에 있는 레코드: 4개
- 고유 문제 레코드: 402개

제어 토큰 불일치 308개의 주요 원인은 다음과 같다.

| 형태 | 수량 | 문제 |
|---|---:|---|
| 플레이어명 `\x1` 제거 | 258 | Windows 번역이 `아돌`로 고정하여 PSP 변수 기능을 잃음 |
| 나머지 줄바꿈 차이 | 50 | `\n` 제거·추가 또는 줄 수 변경 |

플레이어 이름을 바꿀 수 있거나 시스템이 `\x1`을 동적으로 치환한다면 `아돌` 고정은 기능 회귀가 된다. `\x1`을 유지하는 형태로 되돌리는 것이 안전하다.

### 2. 루비 및 마크업 제거

- 루비 태그가 원문에는 있지만 번역에서 사라진 문장: 136개
- 이 중 현재 설정상 즉시 검증 오류가 되는 마크업 불일치: 98건

Windows판은 일본어 독음용 루비를 제거하고 본문만 남긴 경우가 많다. 한국어에는 루비가 불필요할 수 있으므로 제거 자체가 반드시 잘못은 아니다. 다만 현재 PSP 검증기는 명시적으로 허용된 항목 외에는 마크업 보존을 요구한다. 태그 제거를 승인하려면 `allow_markup_change` 정책을 체계적으로 적용해야 한다.

### 3. 런타임 many-to-many 대응 — 26개 레코드

검증 오류 402개를 제외한 뒤에도 `ridepedestal.xso` 공유 payload가 `many_to_many`로 연결되어 빌더가 중단됐다.

- 관련 레코드: 26개
- 동일 XSO 해시가 세 standalone 경로와 세 런타임 아카이브에 대응
- 현재 빌더는 정확히 어느 런타임 복사본을 바꿀지 유일하게 결정할 수 없어 거부

이 항목은 런타임 경로를 모두 안전하게 갱신하는 별도 지원이 필요하다.

### 4. 공유 payload 번역 충돌 — 134개 레코드

같은 XSO payload와 문자열 인덱스를 여러 PSP 경로가 공유하지만 경로별 번역문이 서로 다른 사례가 있다.

- 충돌 그룹: 66개
- 관련 레코드: 134개

실제 런타임 payload는 하나이므로 서로 다른 번역을 동시에 넣을 수 없다. 문맥을 비교해 하나의 공통 번역을 정하거나, 런타임 payload를 분리할 수 있는지 추가 분석해야 한다.

### 5. PSP 코덱 미지원 문자 — 27개 레코드

Windows 번역에서 쓰인 다음 문자들이 현재 PSP 인코더에 매핑되지 않아 빌드가 중단된다.

| 문자 | 전체 출현 수 |
|---|---:|
| `─` | 26 |
| `～` | 12 |
| `《`, `》` | 각 4 |
| `②` | 2 |
| `①`, `③`, `ㆍ`, `★` | 각 1 |

미지원 문자 중 하나 이상을 포함하는 레코드는 27개다. 일반 구두점으로 정규화하거나 PSP 글리프 매핑을 추가해야 한다.

## 추가로 발견된 고위험 데이터

### 독립된 백슬래시 — 15개

15개 번역에 `\n`, `\x1` 같은 정상 토큰이 아닌 단독 `\`가 들어 있다.

예:

- `정령들에의\감사의 마음을`
- `그걸\오르하에게 넘겨주게.`
- `제국에\남겨두고 온 가족`

문맥상 대부분 Windows판 줄바꿈이 PSP용 `\n`으로 변환되지 않은 것으로 보인다. 그대로 인코딩되면 줄바꿈이 아니라 백슬래시 문자 또는 예상하지 못한 제어 동작이 될 수 있다. 15개 모두 수동 또는 자동 정규화가 필요하다.

### Windows/PSP 비정확 대응 — 43개

계획 036에서 Windows판 exact 대응으로 교체하지 못하고 기존 번역을 보존한 43개가 전체 draft에 포함되어 있다. 기술적으로 빌드 가능한 항목도 있지만 Windows판 경로·인덱스 대응 근거가 약하므로 별도 검수가 필요하다.

주요 파일은 다음 계열이다.

- `s_0202/_waitingoruhaanduru`
- `s_0203/talkoruha2`
- `s_0202`, `s_0203/aboutreda`

### 화면 폭 및 줄바꿈 위험

보수적인 고정폭 추정에서 다음을 발견했다.

- 한 줄이 한글 24자 상당을 넘는 문장: 26개
- 원문보다 줄 수가 증가한 문장: 15개
- blocker를 제외한 preflight 호환 집합에서도 긴 문장: 8개

대표 위험 문장에는 `talkodo`, `talktera`, `talkkuvaru`, `talktokusa`, `talkoruha3` 등이 있다. 일부는 앞서 발견한 단독 백슬래시 때문에 실제 줄바꿈이 사라져 한 줄이 더 길어졌다.

### 번역 품질

Windows판 번역에는 다음과 같은 오래된 번역체와 오탈자 표본이 확인됐다.

- `속물같인것 같아`
- `아돌는`
- `프라이베이트 룸`
- `돌릴수`, `건널수`
- 직역투 및 불규칙한 띄어쓰기

이는 빌드를 막지는 않지만 전체 무검수 적용 시 그대로 게임에 표시된다.

- 제어 토큰·마크업 문제 402개

## 권장 다음 단계

전체를 바로 override로 바꾸지 말고 다음 순서로 정리하는 것이 좋다.

1. `\x1`을 `아돌`로 풀어 쓴 258개를 PSP 변수로 복원한다.
2. 단독 백슬래시 15개를 문맥에 맞게 `\n`으로 고친다.
3. 루비 제거 136개에 대해 한국어용 마크업 변경 허용 정책을 적용한다.
4. 미지원 문자 9종을 지원 문자로 정규화하거나 글리프를 추가한다.
5. 공유 payload 충돌 66그룹의 번역을 하나로 통합한다.
6. many-to-many `ridepedestal` 런타임 매핑을 빌더에서 지원한다.
7. 비정확 대응 43개와 긴 문장 26개를 GUI에서 우선 검수한다.
8. 정리 후 4,628개 전체 preflight를 다시 실행한다.
