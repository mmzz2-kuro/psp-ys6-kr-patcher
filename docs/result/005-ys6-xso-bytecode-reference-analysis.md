- 일반 대화, `seltalk`, `endtalk`, 독백, 캡션, 보스 이벤트, 플래그 조작 계열 포함

## 구조 스캔 결과

- `.z` 해제: 31/31 성공
- XSR 구조 검사: 31/31 성공
- 포맷 변형 또는 CP932 오류: 0개
- 문자열: 총 363개
- 헤더 `0x04~0x1B` 값은 31개 모두 동일
- 명령 영역 마지막 opcode는 31개 모두 `000001`이며 원시 워드는 `00 00 00 01`
- 문자열이 없는 플래그 전용 XSR도 동일 구조로 정상 처리됨

## 바이트코드 명령 구조

4바이트 명령 워드의 첫 바이트는 뒤따르는 u32 인자의 개수다.

```text
command_word[0]   = argument_count
command_word[1:4] = opcode 식별 바이트
arguments         = argument_count × u32 little-endian
```

- 인자 수 0~7이 실제 표본에서 확인됐다.
- 이 규칙으로 31개 파일의 명령 영역을 시작부터 오프셋 테이블 직전까지 오차 없이 파싱했다.
- 명령 경계 가설은 표본 범위에서 확정으로 취급한다.

## 문자열 참조 opcode

opcode 표기는 명령 워드의 인자 수 바이트를 제외한 뒤 3바이트를 원시 순서대로 16진수화한 값이다.

### 확정 또는 강하게 교차 검증됨

#### `100502`, 인자 4개

- 원시 명령 워드 예: `04 10 05 02`
- `arg3`: 본문 문자열 인덱스
- `arg2`: 선택적 화자명 문자열 인덱스. 화자명이 없을 때 `0xFFFFFFFF` 등 비문자열 값 사용
- `arg3`만으로 24개 파일에서 349회 본문 참조 확인
- `娘の声` 같은 화자명은 `arg2`, 다음 대사는 `arg3`에서 한 명령으로 함께 참조됨

#### `500502`, 인자 2개

- `arg0`: 선택지 표시 문자열
- `arg1`: 선택 결과 심볼 문자열
- 예: `話をする` + `SelTalk`, `はい` + `SelYes`, `いいえ` + `SelNo`
- 5개 파일, 12개 명령에서 같은 쌍 구조 확인

#### `900602`, 인자 1개

- `arg0`: 선택 프롬프트 문자열
- 예: `選んでください`
- 선택지 구조가 있는 파일에서 반복 확인

#### `800302`, 인자 2개

- `arg0`: 맵 또는 스크립트 경로 문자열
- 예: `s_02\\s_0202\\`, `s_70\\s_7000\\`, `s_10\\s_1016\\`
- `arg1` 의미는 미확정

### 유력하지만 의미 세분화가 필요한 후보

- `F00402 arg0`: `map_name12` 같은 캡션 자산명 참조
- `900302 arg0`: `t220a`, `boss_name00`, `tonbo_loop` 같은 자산·오브젝트명 참조
- `A01002 arg0`: `StartBossBattle` 같은 함수 또는 이벤트 심볼 참조
- `100602 arg0`: `f_0003` 같은 심볼 후보 참조

이 후보들은 해당 인자의 정수값이 문자열 인덱스와 일치하고 문맥도 자연스럽지만, opcode의 전체 동작 의미는 아직 확정하지 않는다.

## 본문 참조에서 제외된 문자열의 분류

`100502 arg3`가 참조하지 않는 문자열은 48개였으며 다음 계열로 분류됐다.

- 빈 문자열
- 선택지 표시문과 선택 결과 심볼
- 선택 프롬프트
- 화자명
- 맵·스크립트 경로
- 캡션·애니메이션·보스명 같은 자산명
- 이벤트 함수 심볼

따라서 “본문 참조에서 누락”된 것이 아니라 다른 opcode 계열이 사용하는 비본문 문자열이다.

## 추출기 보강

`/tools/scripts/ys6_xso.py`에 다음 기능을 추가했다.

- 명령 스트림 경계 검증
- 명령별 opcode, 인자 수, u32 인자 파싱
- 문자열 인덱스일 가능성이 있는 인자 위치 표시
- `code-stats` JSON 명령
- 꺾쇠 마크업 보존 및 빈도 집계

사용 예:

```powershell
python tools\scripts\ys6_xso.py code-stats input.xso --include-commands
```

## 재삽입 영향 평가

- 문자열 길이 변경 시 문자열 오프셋 테이블을 재계산해야 한다.
- 바이트코드는 문자열을 테이블 인덱스로 참조하므로 기존 문자열의 순서와 개수를 유지하면 명령 영역을 수정하지 않고 본문 길이를 변경할 가능성이 높다.
- 문자열 인덱스 순서를 바꾸거나 문자열을 추가·삭제하면 본문, 화자, 선택지, 심볼 및 경로 참조를 모두 갱신해야 한다.
- 파일 크기 증가에 따른 런타임 버퍼 및 압축 크기 한계는 아직 미검증이다.
