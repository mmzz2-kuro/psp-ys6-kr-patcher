## 결론

게임 시작 시 첫 번째로 표시되는 `s_0551.xso.z`의 문자열 인덱스 35를 동일한 CP932 길이의 일본어 시험문으로 교체했다. 수정 파일은 기존 한 섹터 안에 들어갔으며, 원본 ISO를 변경하지 않고 `/patched`에 작업 ISO 하나를 생성했다.

## 검증 결과

- 원본 대상 `.z` 크기 1,946바이트와 SHA-256 `A4739D20087BE616D1A22B9E87FD5B638C42DA800C48A0941BCEABA910B9CC2A`를 확인했다.
- 원문과 시험문이 모두 CP932 22바이트임을 교체 도구가 확인했다.
- 수정 XSR의 헤더·명령부가 원본과 동일하다.
- 수정 `.z`의 CRC32, 비압축 크기, zlib 종료 및 잔여 바이트 0을 확인했다.
- ISO 9660 LE/BE 파일 크기 필드를 1,951바이트로 갱신했다.
- 대상 데이터 섹터와 크기 필드 밖 변경은 0건이다.
- 작업 ISO에서 대상 파일을 다시 추출한 결과 준비한 수정 `.z`와 SHA-256이 일치했다.
- 재해제 XSR도 준비한 수정 XSR과 SHA-256이 일치했다.
- 재추출된 문자열 인덱스 35가 `これはテスト表示です。`임을 확인했다.
- 작업 ISO가 이미 있을 때 덮어쓰기 옵션 없이 재실행하면 정상적으로 거부했다.
- 전체 단위 테스트 30개와 Python 바이트코드 컴파일이 통과했다.

첫 ISO 패치 시 기대 대상 SHA-256 인수의 마지막 문자 `A`를 누락해 안전 검사에서 작업 전 중단됐다. 출력 ISO가 없는 것을 확인한 뒤 정확한 64자리 해시로 재실행했으며 최종 산출물에는 영향이 없다.
