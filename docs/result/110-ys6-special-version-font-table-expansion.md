# 110. Ys VI SPECIAL VERSION 한글 폰트 테이블 확장 결과

상태: 최소 확장 증명 완료 (사용자 실기 확인)

## 1차 실기 실패와 수정

- 1차 증명 ISO에서는 시스템 메시지와 대화 글자가 모두 표시되지 않았다.
- 원인은 신규 폰트 `PT_LOAD`가 프로그램 헤더 index 3에 있었지만 여섯 PSP 재배치 엔트리의 target segment를 index 2로 기록한 것이었다.
- index 2에는 기존 `0x700000A0` PSP relocation 헤더가 있었으므로 폰트 검색 함수가 신규 테이블 주소를 얻지 못한 증상과 일치한다.
- 교정본에서는 신규 `PT_LOAD`를 index 2로 옮기고 기존 PSP relocation 헤더를 index 3으로 이동했다.
- 교정본의 여섯 재배치 엔트리 target은 모두 index 2이며, 재배치를 적용한 세 주소 구성 결과가 모두 `0x360000`임을 다시 확인했다.

## 수행 내용

- 일반판의 26바이트 폰트 순회 코드와 SPECIAL VERSION의 30바이트 순회 코드를 재배치 적용 후 명령 패턴으로 교차 비교했다.
- SPECIAL VERSION의 폰트 검색 함수가 파일 오프셋 `0x2D518` 부근에 있고, 동일 테이블을 조회하는 검색 경로가 세 곳임을 확인했다.
- 실제 테이블 시작은 `0x15EAD0`, 레코드 수는 1,774개다. 기존 `0x15EB2A`/1,771개 분석은 앞쪽 내부 레코드 3개를 제외한 화면 글리프 구간이었다.
- 기존 1,774개 레코드를 바이트 단위로 보존한 채 ELF의 신규 읽기 전용 `PT_LOAD` 영역 `0x360000`으로 복제했다.
- 사용자 정의 Shift-JIS 코드 `0xF040`~`0xF04F`에 신규 한글 16자를 append하고 검색 상한을 1,790개로 확장했다.
- 세 주소 참조의 `R_MIPS_HI16`/`R_MIPS_LO16` 대상 세그먼트를 신규 영역으로 변경했다.
- 확장 BOOT/EBOOT은 기존 ISO 파일을 덮어쓰지 않고 ISO 끝의 신규 extent에 각각 배치했으며, 디렉터리 레코드와 볼륨 섹터 수를 갱신했다.
- 초반 `s_0551` 첫 장면에서 신규 글리프를 바로 확인할 수 있도록 `겼`, `낌`을 사용하는 두 문장을 독립 IDM과 런타임 아카이브 복사본에 함께 반영했다.

## 검색 루틴 근거

- 직접 조회 함수: `0x2D518`~`0x2D550`
- 테이블 주소 구성 쌍:
  - `0x2D518` / `0x2D520`
  - `0x2D72C` / `0x2D730`
  - `0x2D7A8` / `0x2D7B0`
- 레코드 순회 크기: 세 경로 모두 `addiu ..., 0x1E`
- 기존 상한 1,774 (`0x06EE`) 참조:
  - `0x2D534`
  - `0x2D744`
  - `0x2D7C4`
- 일반판의 대응 코드는 같은 구조에서 레코드 크기 26, 상한 4,608을 사용하며 가장 높은 비교 점수는 25개 명령 중 21개였다.

## 최소 확장 구성

- 신규 글리프: `겼`, `낌`, `감`, `갑`, `값`, `갓`, `갖`, `갛`, `개`, `객`, `갯`, `걷`, `검`, `겁`, `겉`, `겪`
- 신규 코드: `0xF040`~`0xF04F`
- 기존 매핑: revision 3, 434자 유지
- 증명 매핑: revision 4, 450자
- 기존 테이블: 1,774개 × 30바이트
- 확장 테이블: 1,790개 × 30바이트 = 53,700바이트
- 기존 데이터 세그먼트 메모리 끝: `0x355E90`
- 신규 세그먼트 시작: `0x360000` (비중첩)

## 초반 확인 문장

- `왜 그러니, 이샤?` → `무슨 일이 생겼니, 이샤?`
- `어쩐지……\n바람이 술렁이는 듯 해서……` → `어쩐지……\n바람이 술렁이는 느낌이 들어서……`
- 첫 문장의 `겼`, 두 번째 문장의 `낌`이 기존 1,774개 이후의 신규 레코드다.

## 사용자 실기 확인 항목

1. 테스트 ISO가 정상 부팅되는지 확인한다.
2. 게임 초반 `s_0551` 장면의 첫 문장에서 `겼`이 정상 표시되는지 확인한다.
3. 이어지는 바람 관련 문장에서 `낌`이 정상 표시되는지 확인한다.
4. 기존 109번 한글과 일본어 글리프가 깨지지 않는지 확인한다.
5. 대화 종료와 장면 진행이 정상인지 확인한다.

사용자가 프로그램 헤더 교정본에서 대사가 정상 표시되는 것을 확인했다. 이에 따라 신규 `PT_LOAD` 적재, PSP 재배치 대상 index 2, 기존 글리프 검색 및 확장 글리프 검색 경로의 실제 실행 검증을 통과한 것으로 판정한다.

## 알려진 사항 및 정리 대상

- 현재 ISO는 확장 구조를 검증하기 위한 16자 증명본이며, 보류된 신규 한글 607자와 IDM 번역 2,477개 전체를 아직 적용하지 않았다.
- `PT_LOAD` 추가 방식은 정적 구조·ISO 재추출·사용자 실기 검증을 통과했다.
- 1차 실패 ISO는 프로그램 헤더 index 오류가 있으므로 사용하지 않는다.
- 실기 확인 후 불필요하면 이번 테스트 ISO를 삭제할 수 있다.
