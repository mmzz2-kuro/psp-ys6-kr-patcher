# 068. Ys VI 저장·불러오기 지역명 문자열 탐색 결과

## 결론

- 저장·불러오기 목록의 지역명은 이미지나 별도 문자 인코딩이 아니다.
- 각 저장 지점 맵의 `save.xso.z` 문자열 풀 index 0에 일반 CP932 문자열로
  저장되어 있다.
- `save.xso`의 첫 명령 `900502`가 index 0을 인수로 사용한다.
- 기존 카탈로그의 역할 규칙에 `900502`가 없어 이 문자열이 `unreferenced`로
  분류됐고, 번역 작업공간에서도 `untranslated`로 남아 패치에서 제외됐다.

## 확인된 예시

### 레다의 집락

- 경로: `PSP_GAME/USRDIR/data/map/s_05/s_0500/save.xso.z`
- XSO SHA-256:
  `73ACB12CB1E5ED50B597D11DC4027EA814E45FD85DAE92843E258BA7CCFEB7FC`
- string index: 0
- XSO 파일 오프셋: `0x34`(52)
- 원문: `レダの集落`
- CP932: `83 8C 83 5F 82 CC 8F 57 97 8E`
- ISO LBA: 163088
- 컨테이너 크기: 53바이트
- 해제 XSO 크기: 64바이트

### 기도의 샘

- 경로:
  - `PSP_GAME/USRDIR/data/map/s_06/s_0600/save.xso.z`
  - `PSP_GAME/USRDIR/data/map/s_06/s_0699/save.xso.z`
- XSO SHA-256:
  `55FB82D357137E0122228B8C35A85283D067CD2960F9E7569BAC100643E11C3E`
- string index: 0
- XSO 파일 오프셋: `0x34`(52)
- 원문: `祈りの泉`
- CP932: `8B 46 82 E8 82 CC 90 F2`
- ISO LBA: 173296, 174064
- 컨테이너 크기: 각각 51바이트
- 해제 XSO 크기: 각각 64바이트

## XSO 구조

- 세 예시 `save.xso`는 모두 다음과 같은 최소 구조다.
  - command 0: opcode `900502`, argument `[0]`
  - command 1: 종료 명령 `000001`
  - string 0: 저장 지점 명칭
- 기존 문자열 추출기는 `900502`의 argument 0을 가능한 문자열 참조로는
  감지하지만 확정 역할 규칙이 없어 `unreferenced`로 기록한다.
- 따라서 `900502`, 인수 1개, argument index 0을 저장 지점 명칭 역할로
  분류하는 것이 구조에 부합한다.

## 전체 범위

- 번역 작업공간의 `save.xso` 레코드: 23개
- 고유 저장 지점 명칭/payload: 18개
- 런타임 매핑에 포함된 실제 독립 경로: 24개
  - 동일 payload인 `_save.xso.z` 복사본 1개 포함
- 18개 payload 모두 `standalone_only` 매핑이며 아카이브 런타임 복사본은 없다.
- 중복 명칭에는 기도의 샘, 망각의 유적 최심부, 로문 함대 기함 선창,
  녹수동 동굴호수, 나피쉬팀의 상자 중추 등이 있다.

## 직접 ISO 검색 결과 구분

- `祈りの泉` CP932 패턴은 ISO 전체에서 두 번 직접 발견됐다.
- 두 위치는 저장명 리소스가 아니라 다음 효과음 설명 주석의 중복 사본이다.
  - `PSP_GAME/USRDIR/data/arc/init.bin` 안의 `effectdef.txt`
  - `PSP_GAME/USRDIR/data/wave/effect/effectdef.txt`
- 문맥은 `祈りの泉・破壊音（仮）`이며 저장 목록 패치 대상이 아니다.
- 실제 `save.xso.z`는 압축 컨테이너이므로 ISO 원시 바이트 검색에서 직접 나오지
  않으며, 컨테이너 해제 후 CP932 문자열이 확인된다.

## 저장/불러오기 동작 판단

- opcode `900502`가 맵별 `save.xso`의 유일한 문자열 index 0을 인수로 받으므로,
  현재 맵에서 저장 지점 표시명을 저장 시스템에 전달하는 구조로 판단된다.
- 저장소에는 실제 PSP 세이브 데이터가 없어 이름 문자열이 세이브 파일에 직접
  복사되는지, 내부 상태에 등록된 뒤 별도 필드로 기록되는지는 확정하지 못했다.
- 기존 세이브 슬롯은 이미 일본어 명칭을 보관했을 가능성이 있으므로 구현 후에는
  새 슬롯 저장과 기존 슬롯 표시를 각각 시험해야 한다.

## 후속 구현 권장 범위

1. `ys6_dialogue_extract.py` 역할 규칙에 `(900502, 1, 0)`을 저장 지점 명칭으로
   추가한다.
2. 23개 `save.xso` 레코드에 18개 고유 한글 명칭을 적용하고 override로 전환한다.
3. 기존 `standalone_only` 그룹 재빌드 흐름으로 24개 독립 경로를 모두 교체한다.
4. GUI 사전 검증에서 18개 그룹과 24개 경로의 할당 여유를 확인한다.
5. 새 ISO에서 새 저장을 만든 뒤 저장·불러오기 목록을 확인한다.
6. 기존 세이브가 일본어로 남으면 새 저장명으로 갱신되는 시점 또는 세이브 파일
   마이그레이션 필요 여부를 별도로 조사한다.

## 변경 및 정리

- 이번 단계에서는 원본 ISO, 번역 데이터 및 패치 코드를 수정하지 않았다.
- 분석용으로 해제한 임시 XSO 3개는 확인 후 삭제했으며 복구할 필요가 없다.
